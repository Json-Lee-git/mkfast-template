## 1. 产品定位

不要做“小红书 AI 文案工具”，要做：

**小红书实物电商选品与内容测试工作台。**

它服务的是一个完整动作链：

```text
发现商品 -> 判断值不值得测 -> 拆对标 -> 生成测试内容
-> 发布 -> 回填数据 -> 复盘决策 -> 放大/调整/放弃
```

这个系统不替代小红书、千帆、商家后台。它解决的是商家后台之前和之外的问题：

- 选什么品。
- 为什么这个品值得测。
- 该模仿谁。
- 第一批笔记怎么发。
- 数据回来后下一步怎么判断。
- 哪些规则和售后风险需要提前避开。

## 2. 无代码原型总结构

第一版建议用 8 张表：

| 表 | 作用 | 优先级 |
| --- | --- | --- |
| `Products` 商品候选库 | 管理所有待测/在测/放弃/放大的商品 | P0 |
| `Suppliers` 供应链表 | 管理货源、成本、履约、售后风险 | P0 |
| `Benchmarks` 对标样本库 | 保存对标店铺、笔记、封面、标题、数据证据 | P0 |
| `Templates` 爆款模板库 | 管理封面、标题、剧情、评论区模板 | P1 |
| `ContentPlans` 内容测试方案 | 为每个商品生成多场景、多版本笔记 | P0 |
| `Publishing` 发布排期表 | 管理账号、发布时间、发布间隔、挂车方式 | P0 |
| `Metrics` 数据回填表 | 记录曝光、互动、加购、成交、退货、负反馈 | P0 |
| `Rules` 规则/风控库 | 管理官方规则、敏感风险和最后核验时间 | P1 |

不建议第一版建太多表。真正重要的是让用户每天能坚持填，并且填完能得到下一步动作。

## 3. Products 商品候选库

### 3.1 字段设计

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 商品名称 | 文本 | 原始商品名，不追求小红书化 |
| 小红书包装名 | 文本 | 内容里准备怎么叫它 |
| 当前状态 | 单选 | 待评估 / 待测 / 测试中 / 放大 / 暂停 / 放弃 |
| 类目 | 单选 | 家居 / 饰品 / 宠物 / 收纳 / 礼物 / 情绪 / 其他 |
| 选品类型 | 多选 | 低成本高毛利 / 低粉高转化 / 小众蓝海 / 季节节点 / 情绪价值 / 场景重构 / 垂直店 |
| 目标人群 | 文本 | 谁会买 |
| 使用场景 | 文本 | 在什么情况下使用 |
| 核心痛点 | 文本 | 解决什么具体问题 |
| 情绪价值 | 文本 | 陪伴、礼物、仪式感、玄学、关系表达等 |
| 节点属性 | 文本 | 夏季、节日、开学、世界杯、IP 热点等 |
| 对标数量 | 关联统计 | 关联 Benchmarks |
| 供应商数量 | 关联统计 | 关联 Suppliers |
| 预估成本 | 数字 | 从供应链表汇总或手动填 |
| 预估售价 | 数字 | 小红书对标售价 |
| 预估毛利率 | 公式 | `(售价 - 成本) / 售价` |
| 近期加购证据 | 数字 | 对标样本中 24 小时加购峰值 |
| 近期销量证据 | 数字 | 对标样本中近期销量峰值 |
| 低粉验证 | 复选 | 是否存在低粉账号卖动 |
| 非标程度 | 评分 | 1-5 |
| 内容可视化 | 评分 | 1-5 |
| 履约风险 | 评分 | 1-5，越高风险越大 |
| 规则风险 | 评分 | 1-5，越高风险越大 |
| 选品总分 | 公式 | 见评分规则 |
| 下一步动作 | 单选 | 补证据 / 做内容 / 小批量测试 / 换供应链 / 放弃 |
| 备注 | 长文本 | 记录判断依据 |

### 3.2 推荐视图

| 视图 | 筛选 |
| --- | --- |
| 今日待评估 | 当前状态 = 待评估 |
| 可进入测试 | 选品总分 >= 70 且 供应商数量 >= 1 |
| 高毛利候选 | 预估毛利率 >= 40% |
| 低粉验证候选 | 低粉验证 = 是 |
| 高风险候选 | 履约风险 >= 4 或 规则风险 >= 4 |
| 已放大商品 | 当前状态 = 放大 |

## 5. Benchmarks 对标样本库

### 5.1 字段设计

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 对标标题 | 文本 | 笔记或商品链接标题摘要 |
| 商品候选 | 关联 | 对应 Products |
| 对标类型 | 单选 | 店铺 / 商品链接 / 笔记 / 封面 / 评论区 |
| 对标链接 | URL | 小红书链接、千帆截图链接或手动记录 |
| 对标账号粉丝数 | 数字 | 用于低粉验证 |
| 对标销量 | 数字 | 商品链接销量 |
| 24h 加购 | 数字 | 近期爆发信号 |
| 24h 购买 | 数字 | 近期成交信号 |
| 近期月销 | 数字 | 长一点的销量信号 |
| 售价 | 数字 | 对标售价 |
| 内容形式 | 单选 | 图文 / 视频 / 商品笔记 / 普通笔记 |
| 是否挂车 | 复选 | 是否商品笔记或带商品链接 |
| 标题结构 | 多选 | 低粉反差 / 价格反差 / 家庭口吻 / 损失叙事 / 场景重命名 / 情绪价值 |
| 封面模板 | 多选 | 大字报 / 商品堆叠 / 手写信 / 快递面单 / 实拍生活场景 / AI 封面 |
| 场景标签 | 多选 | 家居 / 礼物 / 宠物 / 办公 / 出行 / 收纳 / 情绪 / 其他 |
| 可迁移点 | 长文本 | 这个样本能被我们借鉴什么 |
| 不可照抄点 | 长文本 | 侵权、虚假、过度营销、类目不适配等 |
| 证据截图 | 附件 | 截图或文件 |
| 证据强度 | 单选 | 强 / 中 / 弱 |

### 5.2 证据强度规则

| 强度 | 标准 |
| --- | --- |
| 强 | 低粉账号 + 近期加购/成交强 + 有明确售价/销量 |
| 中 | 有销量或加购，但缺少粉丝数、成本或时间证据 |
| 弱 | 只有内容感觉好，没有交易或加购证据 |

系统要逼用户至少添加 3 条对标证据，否则不允许进入内容测试。因为没有对标，AI 很容易变成凭空创作。

| 模板 | 系统解释 |

| 字段 | 类型 | 说明 |

### 7.1 每个商品的最低内容包

一个商品进入测试前，至少准备：

- 3 个场景方向。
- 每个场景 3 条标题。
- 每个场景 1 个封面方向。
- 至少 1 条商品笔记。
- 至少 1 条普通笔记。
- 至少 1 条用户反馈/干货/互动笔记。

这来自运营技巧里的一个核心点：店铺不要只有卖货笔记，也要有日常、反馈、干货、互动，让账号看起来更真实。

### 8.1 发布纪律

资料里的建议可以沉淀成初版规则：

- 单账号日更 3-5 条较稳。
- 超过 5 条要关注间隔和账号状态。
- 同一账号发布间隔至少 1 小时。
- 更大发布量通过关联号解决。
- 不建议新手一开始用定时发布。
- 每周注意笔记中心任务，能拿系统流量奖励就拿。

这些先作为运营提示，不做强制自动化。

第一版不要假装规则全自动。更现实的做法是：

- 规则库先手动维护。
- 每条内容方案可以打风险标签。
- 进入发布前做一次风控检查清单。

## 11. 选品评分规则

### 11.1 总分结构

满分 100：

| 维度 | 分值 | 说明 |
| --- | ---: | --- |
| 毛利空间 | 15 | 利润够不够覆盖试错 |
| 低粉验证 | 15 | 是否有低粉账号卖动 |
| 近期热度 | 15 | 24h 加购、近期销量、评论需求 |
| 内容可视化 | 10 | 是否容易拍/做出好内容 |
| 场景强度 | 10 | 是否有具体人群、动作和痛点 |
| 非标程度 | 10 | 是否不容易被直接比价 |
| 供应链可行性 | 10 | 是否能代发、小批量、稳定补货 |
| 履约风险 | -10 | 大件、破损、尺码、质量、退货 |
| 规则风险 | -10 | IP、功效、玄学、AI、虚假承诺 |
| 扩展空间 | 5 | 是否能扩场景、扩 SKU、扩人群 |

### 11.2 评分解释

| 分数 | 结论 | 动作 |
| ---: | --- | --- |
| 80-100 | 强测试候选 | 进入 7 天内容测试 |
| 65-79 | 可测试候选 | 补对标或供应链证据后测试 |
| 50-64 | 观察候选 | 不急着发，继续找证据 |
| 低于 50 | 暂不测试 | 放弃或重构场景 |

评分不是为了追求绝对准确，而是为了阻止新手凭感觉乱发。

## 12. 数据复盘决策规则

### 12.1 24 小时判断

| 信号 | 可能原因 | 下一步 |
| --- | --- | --- |
| 曝光低，点击也低 | 封面/标题没有进入流量池 | 换封面、换标题 |
| 曝光低，但互动率高 | 样本小，但内容可能有潜力 | 保留方向，再发 3 条变体 |
| 曝光高，互动低 | 内容吸引力弱或人群不准 | 换场景或换标题承诺 |
| 收藏高，成交低 | 用户感兴趣但信任/价格/链接弱 | 强化证据、评价、使用场景 |
| 评论多，成交低 | 用户有疑虑 | 把评论问题做成下一批内容 |
| 加购高，成交低 | 价格、信任、运费、规格或详情页问题 | 查商品详情页和优惠 |
| 成交有，退货高 | 预期管理或品质问题 | 改详情、换供应链、暂停放大 |

### 12.2 7 天判断

| 结果 | 决策 |
| --- | --- |
| 多条笔记都有加购/成交 | 进入放大，增加发布量和场景 |
| 只有某一类封面有效 | 固化封面模板，扩标题和正文 |
| 只有某一场景有效 | 商品重命名，围绕该场景做垂直内容 |
| 互动不错但没成交 | 查价格、详情页、信任状和评论区 |
| 完全无信号 | 放弃或换成另一个商品 |
| 成交不错但退货高 | 暂停放大，优先解决供应链和预期管理 |

## 13. 7 天测试节奏

### Day 0：准备

- 录入商品和供应链。
- 添加至少 3 条对标。
- 打选品评分。
- 生成 9 条内容方案。
- 规划 7 天发布表。

### Day 1-2：小样本测试

- 每天 3 条。
- 至少覆盖 2 个场景。
- 至少 1 条商品笔记，1 条普通笔记。
- 记录 24 小时数据。

### Day 3-4：保留有效方向

- 停掉无信号方向。
- 对有效封面/标题做变体。
- 把评论区问题转成内容。
- 检查商品详情页和挂车方式。

### Day 5-7：放大或放弃

- 有加购/成交：加大同方向笔记数量。
- 有互动无成交：补信任、补详情、补评论区。
- 无信号：停止该商品，保留样本进入知识库。
- 有售后风险：先处理供应链。

## 14. AI 在系统里的正确位置

AI 不是第一步，也不是最后裁判。它应该出现在这些位置：

| 环节 | AI 可以做什么 |
| --- | --- |
| 商品理解 | 分析人群、场景、痛点、卖点 |
| 对标拆解 | 拆标题结构、封面机制、正文结构 |
| 内容扩展 | 把一个有效场景扩成多条笔记 |
| 封面方向 | 根据对标封面生成拍摄/制图方案 |
| 素材挖掘 | 生成干货、互动、科普、反馈类选题 |
| 复盘建议 | 根据数据提出下一批动作 |
| 店铺诊断 | 根据店铺内容结构和指标找短板 |

AI 不应该做这些事：

- 编造客户反馈。
- 编造成交截图。
- 编造清仓、倒闭、退货事实。
- 鼓励侵权热点周边。
- 替用户判断供应商是否可靠。
- 替用户承诺效果。

## 15. 第一版原型验收标准

如果无代码原型能完成下面 5 件事，就值得进入开发讨论：

1. 用户能在 15 分钟内录入一个商品候选。
2. 用户能基于 3 条对标样本得到一个选品评分。
3. 用户能生成 7 天测试计划。
4. 用户每天只需 3 分钟回填核心数据。
5. 系统能给出明确下一步动作，而不是只展示数据。

最关键的是第 5 条。工具的价值不是“记录”，而是让用户不再乱猜下一步。

## 16. 下一步讨论建议

下一轮可以直接围绕三个问题讨论：

1. 第一版到底服务新手，还是服务已有货源的小商家？
2. 我们先做飞书多维表格原型，还是先写产品 PRD？
3. 是否挑 3 个真实商品样本，把这套字段完整跑一遍？

我的建议：先挑 3 个商品样本跑字段。跑完之后，开发范围会自然浮出来。
