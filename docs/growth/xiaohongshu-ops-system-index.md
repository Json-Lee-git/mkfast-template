# 小红书运营系统调研包索引

> 阶段：调研收束。
> 用途：作为整套资料的总入口，方便下一轮讨论产品方向、验证路径和开发边界。
> 当前状态：可以进入产品讨论，但不建议直接开发。

## 1. 先看结论

这批资料已经足够支撑一个完整运营系统的雏形。

但这个系统不应该叫“小红书 AI 文案工具”。调研后更准确的产品入口是：

**小红书商品测试助手。**

它的后台能力可以定位为：

**小红书实物电商选品与内容测试工作台。**

它的核心不是“写笔记”，也不是让小白维护表格，而是让用户先从商品链接/截图进入，再完成这个闭环：

```text
商品链接/截图 -> 商品初筛 -> 对标搜索词 -> 对标采集/筛选
-> 内容测试 -> 数据回填
-> 复盘决策 -> 放大/调整/放弃 -> 模板和规则沉淀
```

第一版建议服务：

**有货源但不会做小红书内容化的小商家。**

不建议第一版服务大品牌、成熟代运营团队，也不建议一开始做自动采集、自动发布或插件。

## 3. 已经沉淀出的确定结论

| 结论 | 证据来源 | 可信度 |
| --- | --- | --- |
| 系统可以做，但不是普通 AI 文案工具 | 飞书 SOP、知识星球样本、系统蓝图、外部对标 | 高 |
| 用户入口应从商品链接/截图开始，而不是从表格开始 | 种子用户小白路径、对标采集讨论、同类工具低门槛体验 | 高 |
| 核心用户更适合先选有货源小商家 | 资料里的选品、供应链、毛利、低粉高转化逻辑 | 中高 |
| 第一版应先验证商品链接诊断、对标采集和 7 天任务 | 小白不愿维护系统，只愿知道今天该做什么 | 高 |
| 差异化不在数据最全，而在下一步动作 | 外部对标显示主流工具偏数据雷达 | 高 |
| AI 应该做拆解、扩展、复盘，不该替人发布或造假 | AI 提效样本、规则核验备忘录 | 高 |
| 风控库必须从第一版存在 | 爆款模板涉及 IP、面单、虚假反馈、功效话术等风险 | 高 |
| 自动采集、自动发布、自动切号不适合第一版 | 平台合规、账号风险、MVP 复杂度 | 高 |
| 当前项目适合承接后续 SaaS/后台，但不适合跳过验证直接开发 | 技术结合备忘录、项目结构审计 | 高 |

## 4. 已分类的核心内容

### 4.1 选品分类

从样本里提炼出的高频选品类型：

- 低成本高毛利
- 低粉高转化
- 小众蓝海/非标品
- 垂直单品店/垂直小店
- 季节/节日/热点套利
- 场景重命名
- 情绪价值/礼物属性
- 供应链优势
- 热门产品周边/寄生需求

这些已经转成了 `Products` 表里的选品类型和选品评分维度。

### 4.2 模板分类

已经抽出的模板类型：

- 老人/家人/厂二代人设
- 退货/清仓/库存压力叙事
- 手写信/客户备注/面单信任状
- 大字报封面
- 低粉高销量数据标题
- 场景重命名
- 情绪陪伴/礼物表达

模板不是让用户照抄，而是拆成：

```text
心理机制 + 视觉形式 + 适配类目 + 风险标签 + 迁移方法
```

### 4.3 运营动作分类

已经沉淀出的运营动作：

- 每周找任务/找平台给流量的机会。
- 商品笔记和普通笔记搭配。
- 多账号不要先自动化，先人工记录账号角色。
- 先自己跑通网感，再用 AI 扩量。
- 每天回填核心数据。
- 用加购、成交、评论疑虑、退货和负反馈判断下一步。

### 4.4 AI 能力分类

适合放进系统的 AI 能力：

- 商品人群分析
- 卖点和场景拆解
- 对标笔记结构拆解
- 标题和封面方向生成
- 7 天测试计划生成
- 数据回填后的复盘建议
- 规则风险提醒

不适合放进第一版的 AI 能力：

- 自动发布
- 自动切号
- 伪造客户反馈
- 伪造成交/面单/清仓事实
- 自动判定合规
- 自动替用户选择供应商

## 5. 系统建议形态

### 5.1 第一阶段：无代码原型

先用飞书多维表格 / Notion / Airtable。

目标不是做漂亮，而是验证：

1. 用户是否愿意录入商品、货源和对标。
2. 选品评分是否能减少拍脑袋。
3. 7 天内容测试计划是否能执行。
4. 数据回填是否能控制在每天 3 分钟。
5. 系统是否真的能给出下一步动作。

### 5.2 第二阶段：半自动 AI 工作台

如果无代码原型跑通，再把 AI 能力产品化：

- 一键拆对标
- 一键生成测试计划
- 一键生成封面/标题方向
- 一键复盘回填数据
- 风险提醒和发布前检查

仍然不做自动发布。

### 5.3 第三阶段：Web SaaS

等流程和留存验证后，再讨论开发 Web 系统：

- 用户账号
- 商品库
- 对标库
- 内容计划
- 数据回填
- 模板库
- 规则库
- AI 助手

进入开发讨论前，必须有这些证据：

| 门槛 | 证明方式 | 当前状态 |

| 3 个真实商品跑完字段 | 无代码表格记录 | 验证方案已设计，真实执行未完成 |
| 每个商品至少 3 条对标 | 对标链接/截图/拆解 | 文档样本已演练，真实商品未完成 |
| 每个商品 9 条测试方案 | ContentPlans 表 | 文档样本已演练，验证方案已设计 |
| 7 天数据回填可执行 | Metrics 表或模拟数据 | 模板和验证节奏已设计，真实回填未完成 |
| 系统能给下一步动作 | 复盘结论记录 | 样本演练已证明方向，需真实验证 |
| 千帆/学习中心规则核验 | 后台截图和规则表 | 待完成 |
| 当前项目接入方式明确 | 技术结合备忘录 | 已完成开发前讨论版 |

这张表很重要：它能防止我们太早进入开发。

## 9. 一句话给下一步

下一步最合适的动作是：

**拿 3 个真实货源商品，用无代码模板跑一遍 7 天小红书内容测试流程。**

跑完后再决定是否开发。

如果跑不通，问题大概率不是技术，而是：

- 字段太重
- 用户不愿填
- 选品证据不够
- 内容测试执行不了
- 数据回来后仍然无法决策

这些问题必须在开发前暴露。
