# 小红书运营系统目标用户访谈指南

> 阶段：调研后的真实用户验证。
> 用途：验证“有货源但不会做小红书内容化的小商家”是否真的需要这套系统。
> 边界：本文不是销售话术，也不是产品演示稿；访谈目标是判断要不要继续验证，不是说服用户认可方案。

## 1. 这次访谈要证明什么

这套系统现在最大的未知，不是技术能不能做，而是目标用户是否真的有这 5 个行为：

| 要验证的问题 | 为什么重要 | 通过标准 |
| --- | --- | --- |
| 用户是否有真实货源 | 没有货源，系统会变成泛内容工具 | 能拿出至少 1 个正在卖或准备卖的商品 |
| 用户是否想做小红书 | 没有渠道意愿，工具价值不成立 | 过去做过、正在做，或愿意 7 天内尝试 |
| 用户是否缺选品判断 | 这是系统第一层价值 | 能说出选品犹豫点和失败经历 |
| 用户是否缺内容测试方法 | 这是系统第二层价值 | 不知道怎么找对标、拆笔记、排测试 |
| 用户是否愿意回填数据 | 没有回填，系统无法复盘 | 愿意连续 7 天每天花 3 分钟记录 |
| 用户愿意为哪种形态付费 | 决定后续做诊断、陪跑、模板、内部后台还是 SaaS | 能说清过去为类似问题花过什么钱、愿意买什么结果 |

访谈结论不要写成“用户觉得不错”。要写成：

```text
这个用户是否值得进入 7 天验证？
如果值得，他/她带哪个商品进入？
如果不值得，是货源问题、执行问题、渠道意愿问题，还是付费意愿问题？
```

## 2. 访谈对象筛选

### 2.1 优先访谈的人

| 类型 | 典型特征 | 为什么优先 |
| --- | --- | --- |
| 有货源小商家 | 有淘宝、拼多多、私域、线下店或档口货源 | 能验证选品和内容测试闭环 |
| 做过小红书但没跑通的人 | 发过笔记，有零散数据，但不知道怎么复盘 | 痛点更明确 |
| 有供应链但缺内容能力的人 | 会选货、会发货，不会小红书表达 | 最贴近第一版用户 |
| 单品店/垂直小店老板 | SKU 不多，决策链短 | 更适合 7 天验证 |
| 低预算试错者 | 不想投大广告，愿意人工执行 | 更需要轻量工作台 |

### 2.2 暂不优先的人

| 类型 | 为什么暂缓 |
| --- | --- |
| 大品牌市场团队 | 决策链长，需求会偏品牌投放和团队协作 |
| 成熟代运营团队 | 已有 SOP 和工具，第一版很难满足专业深度 |
| 纯内容博主 | 没有商品和货源，验证会偏账号增长 |
| 只想自动发笔记的人 | 容易把系统带向自动化和合规风险 |
| 没有任何执行时间的人 | 7 天验证无法完成 |

## 3. 访谈前准备

每个受访者访谈前，至少准备这些信息：

| 信息 | 获取方式 |
| --- | --- |
| 受访者身份 | 店主、操盘手、兼职卖货、供应链负责人 |
| 当前卖什么 | 类目、客单价、毛利、库存或供应稳定性 |
| 当前渠道 | 淘宝、拼多多、抖音、小红书、私域、线下 |
| 小红书状态 | 没做过、试过、在做、做过但停了 |
| 访谈目标 | 判断是否进入 7 天验证，不做销售 |

访谈时不要先讲完整方案。先问真实情况，再用一两个概念测试反应。

## 4. 30 分钟访谈结构

| 时间 | 模块 | 目标 |
| ---: | --- | --- |
| 0-3 分钟 | 背景确认 | 确认身份、商品、渠道、小红书经验 |
| 3-10 分钟 | 现状和痛点 | 找真实问题，不引导答案 |
| 10-17 分钟 | 选品和对标 | 判断是否缺方法、是否愿意补证据 |
| 17-23 分钟 | 内容测试和回填 | 判断是否愿意执行 7 天流程 |
| 23-27 分钟 | 方案反应 | 简要展示系统闭环，测试价值感 |
| 27-30 分钟 | 进入验证判断 | 确认商品、时间、配合意愿 |

## 5. 访谈问题

### 5.1 背景确认

1. 你现在主要卖什么商品？
2. 这些商品的货源是自己的、代理的、批发的，还是一件代发？
3. 大概客单价、毛利、库存压力是什么样？
4. 现在主要在哪些渠道卖？
5. 小红书现在是什么状态：没做、试过、正在做，还是做过停了？

记录重点：

| 重点 | 判断 |
| --- | --- |
| 是否有真实商品 | 没商品就不进入验证 |
| 是否有供应稳定性 | 不稳定则只做访谈，不做 7 天发布 |
| 是否有毛利空间 | 毛利太低会影响投放和试错空间 |
| 是否有小红书意愿 | 没意愿不强行验证 |

### 5.2 现状和痛点

1. 如果让你现在用小红书卖这个商品，你最卡在哪里？
2. 之前发过笔记吗？哪条数据最好？为什么觉得它好？
3. 你现在怎么判断一个商品适不适合小红书？
4. 你会看对标吗？一般看什么？
5. 你有没有遇到过“看别人能卖，自己发了没反应”的情况？
6. 你复盘时主要看什么数据？
7. 你最希望有人帮你解决的是选品、内容、拍摄、发布、复盘，还是规则？

不要问：

- 你需不需要一个小红书运营系统？
- 你觉得 AI 工具有没有用？
- 如果免费你会不会用？

这些问题太容易得到礼貌性答案。

### 5.3 选品和对标

1. 你最近最想测的 1 个商品是什么？
2. 为什么选它？依据是什么？
3. 能不能现在说出 3 个小红书上类似商品或类似内容？
4. 如果找不到 3 个对标，你会怎么判断要不要做？
5. 你能接受系统要求你先补 3 条对标，再进入内容测试吗？
6. 对标里你最想知道什么：标题、封面、销量、评论、价格、账号粉丝，还是投流情况？

关键判断：

| 反应 | 含义 |
| --- | --- |
| 能主动说出对标 | 用户已有基础，适合测试工具提效 |
| 完全不知道怎么找 | 系统需要增加“对标发现指导” |
| 抗拒补证据 | 不适合第一批验证 |
| 只想要爆款答案 | 风险较高，容易期待一键发财 |

### 5.4 内容测试和回填

1. 如果一个商品要测 7 天，你觉得每天能投入多少时间？
2. 你能接受每天记录浏览、点赞、收藏、评论、加购或成交吗？
3. 哪些数据你能拿到？哪些拿不到？
4. 如果系统每天只让你填 5 个数，你能坚持吗？
5. 如果 7 天后系统建议“放弃这个商品”，你会接受吗？
6. 如果系统建议“补对标，不要发”，你会觉得有价值还是觉得麻烦？

关键判断：

| 反应 | 含义 |
| --- | --- |
| 愿意每天 3 分钟回填 | 可以进入验证 |
| 只能偶尔看数据 | 适合访谈，不适合 7 天验证 |
| 不愿意接受放弃建议 | 系统决策价值会被削弱 |
| 只要文案不要复盘 | 不是第一版核心用户 |

### 5.5 方案反应测试

在问完真实情况后，再用 60 秒讲方案：

```text
我们不先做一个自动写文案工具，而是先做一个小红书实物电商选品与内容测试工作台。

它会让你先录入商品和货源，再补 3 条对标，然后生成 7 天内容测试计划。
每天只回填少量数据，最后系统给出下一步动作：放大、调整、补证据、暂停或放弃。
```

然后问：

1. 这套流程里，你觉得最有用的是哪一段？
2. 最麻烦的是哪一段？
3. 如果只保留一个功能，你希望保留什么？
4. 如果必须删一个环节，你希望删什么？
5. 你愿意拿一个真实商品跑 7 天吗？
6. 如果跑完后真的帮你少走弯路，你觉得它更像工具、顾问、课程，还是代运营？

注意：不要问“你愿意付多少钱”作为唯一付费验证。更好的问法是：

1. 你现在为类似问题花过钱吗？花在哪？
2. 如果这个流程有人陪你跑 7 天，你会愿意付费吗？
3. 你更愿意为结果付费、为工具订阅付费，还是为陪跑服务付费？
4. 什么情况下你会觉得“不值得付费”？

## 7. 用户评分表

每个用户访谈后打分，不要只靠感觉。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 货源真实性 | 没有商品 | 有商品但不稳定 | 有真实稳定商品 |
| 小红书意愿 | 不想做 | 想了解 | 愿意 7 天内尝试 |
| 选品痛点 | 不觉得卡 | 有点犹豫 | 明确缺判断方法 |
| 内容测试痛点 | 只想随便发 | 需要文案 | 明确缺测试节奏 |
| 对标配合度 | 不愿找对标 | 愿意看但不会找 | 愿意补 3 条对标 |
| 回填配合度 | 不愿记录 | 偶尔记录 | 愿意每天 3 分钟 |
| 复盘接受度 | 只接受正向建议 | 可接受调整 | 可接受放弃/暂停 |
| 付费信号 | 没花过钱也不愿花 | 愿意低价试 | 已为类似问题付费 |

判断标准：

| 总分 | 判断 | 动作 |
| ---: | --- | --- |
| 13-16 | 强匹配 | 邀请进入 7 天验证 |
| 10-12 | 可观察 | 可做访谈样本，暂不优先验证 |
| 7-9 | 弱匹配 | 记录洞察，不进入验证 |
| 0-6 | 不匹配 | 排除第一批用户 |

额外硬门槛：

- 没有真实商品：不进入 7 天验证。
- 不愿回填数据：不进入 7 天验证。
- 只想自动发布：不进入第一批验证。
- 商品明显高风险且无法补证据：不进入真实发布。

## 8. 访谈后如何收束

3 个访谈完成后，不要只写访谈纪要，要输出这张判断表：

| 问题 | 结论 | 证据 |
| --- | --- | --- |
| 第一版用户是否成立 | 成立 / 不成立 / 需要缩窄 | 哪些用户强匹配 |
| 货源商品是否足够 | 足够 / 不足 | 可进入验证的商品数 |
| 用户是否愿意补对标 | 愿意 / 抗拒 | 访谈中的具体反应 |
| 用户是否愿意回填 | 愿意 / 抗拒 | 能接受的回填频率 |
| 用户最看重什么 | 选品 / 对标 / 内容 / 复盘 / 风控 | 原话摘要 |
| 最大阻力是什么 | 字段重 / 不会找对标 / 没时间 / 怕违规 | 原话摘要 |
| 是否启动 7 天验证 | 是 / 否 / 先调整模板 | 决策理由 |

## 9. 和产品讨论的关系

访谈不是替代产品讨论，而是让产品讨论变得具体。

下一轮会议前，如果还没有真实用户访谈，就只能讨论方向：

- 用户画像是否合理。
- 验证路径是否合理。
- 开发门槛是否合理。

完成 3 个访谈后，会议可以讨论更具体的问题：

- 哪 1-3 个商品进入 7 天验证。
- 哪些字段必须删掉。
- 哪些环节用户愿意配合。
- 系统最先应该解决选品、对标、内容计划，还是复盘。
- 后续如果开发，第一版应该更像工具、陪跑台账，还是内部运营后台。

## 10. 一句话结论

这份访谈指南要回答的不是“用户喜不喜欢这个想法”。

它要回答的是：

**有没有 3 个真实小商家，愿意拿真实商品，按这套流程跑 7 天，并接受系统给出的下一步经营动作。**
