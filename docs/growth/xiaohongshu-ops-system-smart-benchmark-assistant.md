# 小红书智能对标采集助手产品方案

> 阶段：调研收束后的产品重构。
> 目的：把“选品与内容测试工作台”改造成小白愿意使用的真实操作流。
> 结论：第一版用户入口不是表格，而是商品链接/截图。

## 1. 一句话定位

第一版不要让用户感觉自己在维护一个运营系统。

应该让用户感觉：

```text
我把一个商品丢进去，系统告诉我：
这个品能不能测、该搜什么对标、哪些笔记值得学、第一周怎么发、数据回来后下一步怎么改。
```

更准确的产品名可以是：

**小红书商品测试助手。**

后台可以仍然是选品、对标、内容、数据、复盘表，但前台必须是小白任务流。

## 2. 第一性原理

小白不是缺“更多数据”，而是缺 4 个判断：

| 小白卡点 | 产品要替他完成的判断 |
| --- | --- |
| 不知道商品能不能做 | 判断是否值得进入测试 |
| 不知道搜什么对标 | 生成小红书搜索词和对标方向 |
| 看不懂对标为什么有效 | 拆标题、封面、场景、评论和风险 |
| 发了以后不知道怎么办 | 根据数据给下一步动作 |

所以第一版的核心不是自动化运营，而是降低试错成本。

```text
少乱选品
少乱写内容
少乱换方向
少在无效商品上继续消耗
```

## 3. 最小可用链路

用户看到的链路：

```text
发商品链接/截图
-> 系统初筛
-> 系统生成对标搜索词
-> 用户打开小红书搜索并采集当前页
-> 系统筛出 3-10 条可学对标
-> 系统生成 7 天任务
-> 用户每天回填截图/数字
-> 系统给下一步动作
```

系统后台链路：

```text
商品识别
-> 关键词生成
-> 对标采集
-> 对标评分
-> 内容任务生成
-> 数据回填
-> 复盘决策
-> 风险沉淀
```

## 4. 三层数据能力

### 4.1 第一版：链接、截图、人工确认

输入：

```text
商品链接
商品截图
货源截图
小红书对标链接
小红书搜索页截图
发布后后台截图
用户手动填写的阅读、点赞、收藏、评论、加购、成交
```

能分析：

```text
商品基础卖点
人群和场景
毛利和履约风险
对标标题和封面结构
评论区需求
内容是否能被小白拍出来
数据表现对应的下一步动作
```

不能承诺：

```text
自动拿到全量小红书后台数据
自动监控所有竞品
自动判断平台推荐原因
自动读取订单、退款、店铺分、广告归因
```

### 4.2 第二版：用户触发的当前页采集

用户主动打开小红书搜索页，然后点：

```text
采集当前页
```

系统只读取用户当前可见的内容，并让用户确认哪些笔记进入对标库。

可采集对象：

```text
标题
封面截图
可见互动数
账号信息
正文片段
评论区高频问题
是否挂商品
```

原则：

```text
用户主动触发
只读当前可见页面
用户确认后入库
不绕登录、不批量爬取、不伪装平台后台能力
```

### 4.3 第三版：API 或服务商能力

只有当前两版验证通过后，再考虑：

```text
小红书开放平台
服务市场能力
商家授权后台数据
第三方数据服务接口
订单、商品、库存、售后、投放数据
```

API 是放大效率，不是验证需求的前提。

## 5. 商品链接诊断器

用户输入一个商品链接或截图后，系统输出 5 块内容：

| 输出 | 说明 |
| --- | --- |
| 商品基础识别 | 品类、价格带、规格、功能、材质、视觉特征 |
| 小红书适配度 | 是否适合图文/视频种草，是否有场景和情绪价值 |
| 风险提示 | 履约、售后、版权、功效、虚假承诺、同质化 |
| 对标搜索词 | 5-15 个可直接搜索的小红书关键词 |
| 下一步 | 进入对标、补货源、补样品、暂停、换品 |

输出必须区分：

```text
确定事实
合理推断
待补证据
```

## 6. 对标采集助手

用户不用自己判断“哪条对标值得学”。

系统对采集到的笔记做 6 类评分：

| 评分项 | 判断问题 |
| --- | --- |
| 相关度 | 这条笔记和商品是否真相似 |
| 可迁移度 | 标题、封面、场景是否能迁移到用户商品 |
| 内容可拍性 | 小白是否拍得出来 |
| 需求强度 | 评论区是否有真实问题和购买意图 |
| 数据信号 | 互动、收藏、评论、挂商品等可见信号是否足够 |
| 风险程度 | 是否涉及侵权、夸大、违规或不可复制条件 |

系统输出：

```text
最值得学的 3 条
适合学标题的 3 条
适合学封面的 3 条
适合学评论需求的 3 条
不要学的高风险笔记
```

## 7. 7 天小白任务台

系统不要把完整表结构暴露给用户。

用户每天只看一个任务面板：

| 时间 | 用户看到什么 |
| --- | --- |
| Day 0 | 上传商品、确认货源、补样品/成本 |
| Day 1 | 发 1-3 条最容易执行的内容 |
| Day 2 | 回填数据，系统判断标题/封面是否要改 |
| Day 3 | 做第一次小复盘：继续、换角度、补证据或暂停 |
| Day 4-6 | 按信号放大有效场景 |
| Day 7 | 输出商品结论和下一轮动作 |

每天回填不超过 3 分钟：

```text
阅读
点赞
收藏
评论
加购
成交
截图
评论里用户问了什么
```

## 8. 下一步动作规则

系统的核心输出不是报告，而是动作。

| 数据现象 | 可能判断 | 下一步 |
| --- | --- | --- |
| 曝光低、互动率高 | 内容有吸引力但分发少 | 换标题/封面再测 |
| 曝光高、互动低 | 首图或选题没打中 | 换场景或换痛点 |
| 收藏高、加购低 | 有兴趣但商品价值不清楚 | 补使用细节、套装、对比证据 |
| 加购高、成交低 | 价格、详情、评价或信任问题 | 查详情页、价格带、发货和评价 |
| 评论集中问规格/材质 | 信息缺失 | 下一条补规格、材质、实拍细节 |
| 3 条内容全无信号 | 商品或对标方向弱 | 暂停或换对标 |
| 售后/履约风险高 | 流量承接危险 | 暂停放大，先补供应链 |

## 9. 同类工具可借鉴点

| 工具类型 | 可学什么 | 不学什么 |
| --- | --- | --- |
| 新红/千瓜 | 对标库、关键词、账号/笔记对象模型、报告化表达 | 大而全品牌数据平台 |
| 灰豚/蝉妈妈 | 商品、笔记、达人、直播等对象拆分 | 复杂监控和投放归因 |
| 新榜小数林 | 链接输入、作品监测、导出、轻量回采体验 | 面向专业运营的数据面板 |
| 小红书服务市场 | 未来服务商/API 路径 | 第一版假装已有平台授权 |

我们的反向差异化：

```text
别人给更多数据，我们给更少但更明确的下一步。
别人服务品牌和投放团队，我们先服务小白和小商家。
别人做监控，我们做 7 天商品测试。
```

## 10. 第一版验收标准

用种子用户验证时，不看功能多不多，只看 6 件事：

| 验收项 | 通过标准 |
| --- | --- |
| 商品链接诊断是否有用 | 用户觉得比直接问 AI 更具体 |
| 搜索词是否有用 | 用户能用系统给的词找到对标 |
| 对标筛选是否省力 | 用户不再需要自己判断哪条值得学 |
| 任务是否能执行 | 用户知道今天拍什么、发什么、改什么 |
| 数据复盘是否清楚 | 用户能理解为什么继续、暂停或放弃 |
| 操作是否不烦 | 第 3 天用户还愿意继续填数据 |

如果这 6 件事成立，再讨论开发。

如果不成立，先砍流程，不做 SaaS。

## 11. 产品优先级

P0：

```text
商品链接/截图诊断
小红书搜索词生成
手动对标链接/截图分析
3 条核心对标筛选
9 条内容任务生成
每日数据回填
下一步动作
风险提示
```

P1：

```text
当前页采集
封面 OCR
评论区需求提取
对标库收藏夹
截图自动识别数据
7 天任务看板
报告导出
```

P2：

```text
商家授权数据
开放平台/API
第三方数据接口
批量商品库
团队协作
付费模板/陪跑交付
```

第一版真正要做好的不是“系统完整”，而是让小白完成这句话：

```text
我知道这个商品下一步该怎么测。
```
