# 小红书运营系统无代码 AI 提示词库

> 阶段：无代码验证。
> 用途：在飞书多维表格 / Notion / Airtable 原型阶段，直接用 AI 辅助商品理解、对标拆解、内容计划、复盘和风控。
> 边界：这些提示词只做分析和生成草案，不自动发布、不自动采集、不伪造数据、不替代人工合规判断。

## 1. 使用原则

AI 在这个系统里不是“爆款制造机”，而是“运营分析助理”。

每次使用都遵守 5 条规则：

1. 只基于用户提供的商品、对标、数据和规则分析。
2. 不编造销量、评价、面单、聊天记录、清仓、授权或用户反馈。
3. 不输出“保证爆单”“必火”“官方认可”等确定性承诺。
4. 不直接生成可发布的最终稿，先生成方向、结构和检查清单。
5. 输出必须能落回表格字段，不能只给泛泛建议。

## 2. 通用系统提示词

后面每个提示词都可以先加这一段：

```text
你是一个小红书实物电商运营分析助理。

你的任务不是制造爆款，也不是替用户发布内容，而是帮助用户把商品、货源、对标、内容计划、数据回填和复盘动作结构化。

你必须遵守：
1. 不编造任何销量、成交、面单、客户反馈、清仓、授权、库存、物流或使用效果。
2. 不输出违规、侵权、夸大功效、虚假营销或无法证实的表达。
3. 如果信息不足，先标记“缺证据”，不要硬生成。
4. 每个建议都要说明依据来自哪个输入字段。
5. 输出要尽量适合填回表格。
```

## 12. 提示词版本记录

无代码验证阶段，建议每次 AI 输出都记录：

| 字段 | 用途 |
| --- | --- |
| Prompt ID | 例如 `P-Product-001` |
| Prompt Version | 例如 `v0.1` |
| 使用日期 | 方便复盘 |
| 输入字段来源 | Products / Benchmarks / Metrics 等 |
| 输出是否可用 | 可用 / 部分可用 / 不可用 |
| 人工修改点 | 记录 AI 哪里不靠谱 |
| 风险命中 | 是否出现虚假、夸大、侵权、过度承诺 |

这件事很重要：以后如果进入开发，真正要产品化的不是“AI 很会写”，而是哪些提示词在真实商品里稳定有用。

## 13. 最小使用顺序

第一轮 7 天验证只需要用 6 个提示词：

1. 商品理解提示词。
2. 对标拆解提示词。
3. 选品评分辅助提示词。
4. 9 条内容测试方案提示词。
5. 发布前风控提示词。
6. 每日数据复盘提示词。

Day 8 再用总复盘提示词。

不要一开始把所有提示词都用上。提示词越多，越容易让用户觉得流程很重。

## 14. 开发前判断

如果无代码阶段发现：

- 用户频繁复制使用某个提示词。
- 某个提示词输出很少需要人工改。
- 某个提示词显著减少用户决策时间。
- 某个提示词能稳定给出下一步动作。

那么它才值得进入后续开发讨论。

如果提示词看起来漂亮，但用户不用、改很多、无法执行，就不要产品化。

一句话：

**先让提示词在真实商品和真实用户手里跑通，再决定要不要把它写进系统。**
