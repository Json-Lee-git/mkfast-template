建议阅读顺序：

1. 先读调研交付总报告，确认最终结论。
2. 再读总索引，确认资料包结构。
3. 再读产品讨论决策稿，确认下一轮要拍什么板。
4. 再读讨论稿，确认产品方向和第一版边界。
5. 再读调研稿，确认为什么不是普通 AI 文案工具。
6. 再读系统蓝图，理解模块关系。
7. 再读样本演练，看 3 个商品如何跑流程。
8. 再读真实商品验证方案，确认怎么跑 7 天测试。
9. 再读无代码 AI 提示词库，确认 AI 怎么辅助拆解和复盘。
10. 再读规则核验备忘录，确认哪些规则必须人工核验。
11. 最后按本文搭无代码表格。

## 1. 表格总览

第一版只建 8 张表：

| 表名 | 中文名 | 必须建 | 说明 |
| --- | --- | --- | --- |
| `Products` | 商品候选库 | 是 | 所有选品的主表 |
| `Suppliers` | 供应链表 | 是 | 成本、代发、履约风险 |
| `Benchmarks` | 对标样本库 | 是 | 对标店铺、笔记、商品链接、证据 |
| `Templates` | 模板库 | 是 | 封面、标题、正文、评论区模板 |
| `ContentPlans` | 内容方案表 | 是 | 每条待发笔记的内容方案 |
| `Publishing` | 发布排期表 | 是 | 什么时候、用哪个账号发 |
| `Metrics` | 数据回填表 | 是 | 每天回填笔记表现 |
| `Rules` | 规则风控库 | 建议 | 规则、风险、核验日期 |

表之间的主关系：

```text
Products 1 - n Suppliers
Products 1 - n Benchmarks
Products 1 - n ContentPlans
Templates n - n ContentPlans
ContentPlans 1 - n Publishing
Publishing 1 - n Metrics
Rules n - n Products / ContentPlans
```

### 2.2 公式

预估毛利率：

```text
if(预估售价 > 0, (预估售价 - 预估成本) / 预估售价, 0)
```

选品总分：

```text
毛利空间分
+ 低粉验证分
+ 近期热度分
+ 内容可视化分
+ 场景强度分
+ 非标程度分
+ 供应链可行分
+ 履约风险扣分
+ 规则风险扣分
+ 扩展空间分
```

系统结论：

```text
if(选品总分 >= 80, "强测试",
if(选品总分 >= 65, "可测试",
if(选品总分 >= 50, "观察",
"暂不测")))
```

| 视图名 | 过滤 |
| --- | --- |
| 今日待评估 | 当前状态 = 待评估 |

### 7.2 发布规则提示

在表格说明里固定写：

- 单账号每日 3-5 条更稳。
- 同账号两条笔记间隔建议至少 1 小时。
- 超量发布优先用关联号。
- 新手不要一开始依赖定时发布。
- 每周检查笔记中心任务。

| 成交金额 | 数字 | 元 | 否 |
| 退款订单 | 数字 | 退款数 | 否 |
| 退货原因 | 多选 | 质量 / 尺码 / 预期不符 / 物流 / 7 天无理由 / 其他 |
| 负反馈 | 数字 | 差评、投诉、品质退货等 | 否 |
| 店铺分 | 数字 | 每周填也可以 | 否 |
| 互动率 | 公式 | 见 8.2 | 是 |
| 加购率 | 公式 | 见 8.2 | 是 |
| 成交率 | 公式 | 见 8.2 | 是 |
| 复盘结论 | 单选 | 放大 / 换封面 / 换标题 / 换场景 / 换价格 / 换供应链 / 放弃 / 继续观察 |
| 复盘备注 | 长文本 | 为什么这么判断 | 否 |

### 8.2 公式

互动率：

```text
if(曝光 > 0, (点赞 + 收藏 + 评论) / 曝光, 0)
```

加购率：

```text
if(曝光 > 0, 加购 / 曝光, 0)
```

成交率：

```text
if(加购 > 0, 成交订单 / 加购, 0)
```

### 8.3 复盘判定参考

| 条件 | 复盘结论 |
| --- | --- |
| 曝光低，互动低 | 换封面 |
| 曝光高，互动低 | 换场景 |
| 收藏高，加购低 | 补商品价值和使用动作 |
| 加购高，成交低 | 换价格 / 查详情页 |
| 成交有，退款高 | 换供应链 |
| 多条笔记有成交 | 放大 |
| 7 天完全无信号 | 放弃 |

## 10. 第一周搭表流程

### Day 1：建表

建 8 张表，只填字段，不追求美观。

### Day 2：录入 3 个商品

先录入：

- 拼豆板。
- 解压/情绪陪伴小物。
- 穿衣镜。

### Day 3：补对标

每个商品至少补 3 条对标：

- 1 条商品链接。
- 1 条爆款笔记。
- 1 条店铺或账号样本。

### Day 4：补供应链

每个商品至少补 1 个供应商。穿衣镜必须补 2 个以上，并记录破损和退货风险。

### Day 5：生成内容方案

每个商品生成 9 条内容方案：

- 3 个场景。
- 每个场景 3 条笔记。
- 商品笔记和普通笔记混合。

### Day 6：排 7 天发布计划

先只排拼豆板，避免同时测太多商品。

### Day 7：模拟回填

不一定真的发布，先模拟几组数据，看复盘结论是否清晰。

## 11. 最小可用标准

这份无代码模板是否成立，看 5 个问题：

1. 商品录入是否能在 15 分钟内完成。
2. 对标证据是否能让选品总分更可信。
3. 内容方案是否能直接指导拍摄/制图/写文。
4. 每天回填是否不超过 3 分钟。
5. 复盘结论是否能给出明确下一步动作。

如果这 5 条成立，再讨论开发就很稳。

## 12. 不要过早加入的功能

第一版不要加：

- 自动采集。
- 自动发布。
- 自动登录账号。
- 自动抓销量。
- 自动判断官方规则。
- 多团队权限。
- 复杂图表。
- 付费投放建议。

先把手工流程跑通。一个能让人每天认真填的表，比一个自动化很多但没人坚持用的系统更值钱。
