## 1. 核验原则

第一版系统不要声称“自动合规”，只能做到三件事：

1. 提醒用户哪些地方可能踩规则。
2. 记录每条规则的来源、版本和最后核验日期。
3. 把高风险动作拦在人工确认之前。

规则来源按可信度分 4 层：

| 等级 | 名称 | 含义 | 系统处理 |
| --- | --- | --- | --- |
| A | 已公开确认 | 官方公开页面可访问，且内容与本系统直接相关 | 可以写入规则库，但仍记录核验日期 |
| B | 官方入口存在 | 官方后台或学习中心入口存在，但细则需要登录核验 | 只能写成待核验规则 |
| C | 私域经验 | 来自飞书 SOP、知识星球、实操问答 | 只能作为运营建议，不能作为平台规则 |
| D | 二手资料 | 来自行业文章、服务商文章、第三方报告 | 只能辅助理解，不进入强规则 |

这套系统真正要防的不是“不知道规则”，而是“把一个经验动作误包装成平台允许的稳定动作”。

## 3. 规则分层表

### 3.1 商品笔记与挂车

| 规则项 | 当前来源 | 证据强度 | 运营影响 | 系统处理方式 | 开发前状态 |
| --- | --- | --- | --- | --- | --- |
| 商品笔记发布规范 | 千帆/学习中心入口线索 | B | 决定笔记字段、图片、视频、商品绑定方式 | `Rules` 表标为高风险待核验 | 必须后台核验 |
| 商品挂车/商品绑定 | 知识星球经验 + 千帆入口 | B/C | 决定一条内容是否能追踪加购和成交 | ContentPlans 必须记录挂车方式 | 必须后台核验 |
| 图片比例、数量、封面规范 | 公开资料线索 + 后台入口 | B/D | 影响素材生成尺寸和发布检查 | 只做“待确认尺寸”字段，不写死 | 必须后台核验 |
| 商品笔记与普通笔记搭配 | 知识星球经验 | C | 影响内容组合，不是规则本身 | 作为运营策略，不作为合规规则 | 可先用经验跑 |

系统提示语建议：

> 发布前请确认该内容是否符合当前千帆商品笔记规范；图片比例、商品绑定、挂车方式以后台最新要求为准。

### 3.2 店铺分、负反馈与售后

| 规则项 | 当前来源 | 证据强度 | 运营影响 | 系统处理方式 | 开发前状态 |
| --- | --- | --- | --- | --- | --- |
| 店铺分 | 知识星球经验 + 商家后台入口 | B/C | 决定是否要降频、暂停、换供应链 | Metrics 每周记录店铺分 | 必须后台核验 |
| 品质分/物流分/服务分 | 知识星球经验 | C | 决定问题归因 | 先拆成 3 个手动字段 | 必须后台核验 |
| 负反馈率 | 知识星球经验 + 商家规则入口 | B/C | 决定是否继续放大某商品 | Metrics 必填负反馈数据 | 必须后台核验 |
| 质量问题退货 | 知识星球经验 | C | 影响供应链筛选 | Suppliers 增加质量退货备注 | 必须后台核验 |
| 7 天无理由退货 | 电商通用逻辑 + 私域经验 | C/D | 影响利润测算 | 不做规则判断，只记录退货原因 | 必须后台核验 |

系统提示语建议：

> 如果某商品带来质量退货、差评、投诉或服务分下降，优先暂停放大，并回查供应链、详情页和承诺话术。

### 3.3 账号、关联号与发布频率

| 规则项 | 当前来源 | 证据强度 | 运营影响 | 系统处理方式 | 开发前状态 |
| --- | --- | --- | --- | --- | --- |
| 一个店铺可关联普通号数量 | 知识星球经验 | C | 决定矩阵发布模块是否成立 | Publishing 记录账号角色，不自动控制账号 | 必须后台核验 |
| 一天多篇笔记间隔 | 知识星球经验 | C | 决定发布排期 | 作为建议间隔，不写成硬规则 | 可先人工执行 |
| 多账号 PC 登录 | 知识星球经验 | C | 影响操作便利性和风控 | 系统不做登录控制 | 不进入 MVP |
| 任务中心流量奖励 | 知识星球经验 + 后台入口 | B/C | 决定每周运营动作 | Publishing 增加任务来源字段 | 必须后台核验 |

第一版不要做自动发布、自动切号、自动登录、自动抢任务。原因很简单：收益不如风险大，而且规则变化后系统容易变成账号风险源。

### 3.4 AI 图片、AI 文案与素材合规

| 规则项 | 当前来源 | 证据强度 | 运营影响 | 系统处理方式 | 开发前状态 |
| --- | --- | --- | --- | --- | --- |
| AI 封面生成 | 知识星球经验 | C | 能提升素材效率 | 允许作为素材流程，不自动标记为合规 | 可先使用 |
| 去 AI 感/去水印 | 知识星球工具线索 | C/D | 可能涉及版权、误导和平台识别风险 | 规则库标中高风险 | 必须人工确认 |
| AI 生成客户反馈 | 爆款模板延伸风险 | C | 容易形成虚假证明 | 系统应直接警告 | 不建议使用 |
| 快递面单/客户备注封面 | 爆款模板样本 | C | 有隐私、虚假交易、误导风险 | 规则库标高风险，默认不推荐 | 必须人工确认 |
| AI 商品效果图 | 知识星球经验 | C | 影响详情页和笔记真实性 | 必须要求“以实物为准”核查 | 必须人工确认 |

系统提示语建议：

> AI 可以提高拆解、选题、标题、封面草图效率，但不能伪造销量、评价、聊天记录、客户备注、物流面单、使用效果或授权关系。

### 3.5 IP、热点、功效与玄学表达

| 规则项 | 当前来源 | 证据强度 | 运营影响 | 系统处理方式 | 开发前状态 |
| --- | --- | --- | --- | --- | --- |
| 热门 IP 周边 | 知识星球样本 | C | 流量强，但侵权风险高 | Products 规则风险默认 -5 到 -10 | 必须核验授权 |
| 世界杯/赛事/影视热点 | 知识星球样本 | C | 短期窗口明显 | 加入“热点有效期”和“授权状态”字段 | 必须核验授权 |
| 情绪陪伴类商品 | 知识星球样本 | C | 内容空间大，但话术风险高 | 禁止治疗、转运、确定性承诺 | 必须人工审 |
| 玄学/风水表达 | 知识星球样本 | C | 转化可能强，但合规边界窄 | 只允许仪式感/陪伴/装饰表达 | 必须人工审 |
| 健康/功效承诺 | 社区规范 + 电商规则入口 | A/B | 高风险 | 默认高风险，不建议新手做 | 必须官方核验 |

系统提示语建议：

> 可以表达“仪式感、陪伴感、装饰价值、礼物属性”，不要承诺治疗、转运、发财、变美、变瘦、改善疾病或确定性结果。

## 4. 规则库字段建议

`Rules` 表不要只写“规则名称 + 摘要”。为了后续能做成系统，建议字段如下：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| Rule ID | 自动编号 | 是 | `R-001` |
| 规则名称 | 文本 | 是 | 如商品笔记发布规范 |
| 规则类型 | 单选 | 是 | 内容 / 商品 / 店铺 / 售后 / 广告 / AI / IP / 账号 |
| 风险等级 | 单选 | 是 | 低 / 中 / 高 / 禁止 |
| 证据强度 | 单选 | 是 | A / B / C / D |
| 官方链接 | URL | 否 | 尽量填官方页面 |
| 后台截图 | 附件 | 否 | 登录后台核验后上传 |
| 规则摘要 | 长文本 | 是 | 用自己的话写，不复制长原文 |
| 影响模块 | 多选 | 是 | Products / Benchmarks / ContentPlans / Publishing / Metrics |
| 触发条件 | 长文本 | 是 | 什么情况要提示 |
| 系统提示语 | 长文本 | 是 | 给用户看的短提示 |
| 禁止动作 | 长文本 | 否 | 明确不能做什么 |
| 最后核验日期 | 日期 | 是 | 规则会变 |
| 核验人 | 人员 | 否 | 谁确认的 |
| 核验状态 | 单选 | 是 | 已核验 / 待核验 / 已过期 |
| 备注 | 长文本 | 否 | 例外情况 |

MVP 里可以只做静态提示，不做自动拦截；但“禁止动作”和“证据强度”一定要有，否则后期很难治理。

## 5. 发布前检查清单

每条待发布内容至少过一次这个清单：

| 检查项 | 是/否 | 处理 |
| --- | --- | --- |
| 是否涉及商品笔记或挂车 | 是则核验商品绑定方式 |
| 是否使用 AI 生成图片 | 是则核查是否与实物一致 |
| 是否出现销量、客户反馈、面单、聊天记录 | 是则核查真实性和隐私 |
| 是否涉及 IP、赛事、影视、明星、品牌元素 | 是则核查授权 |
| 是否涉及健康、功效、玄学、情绪疗愈 | 是则弱化承诺，必要时放弃 |
| 是否有夸大效果或确定性收益 | 是则改写或删除 |
| 是否存在导流、私域、联系方式 | 是则按平台规范核验 |
| 是否会拉高退货或负反馈 | 是则回查供应链和详情页 |

这张表的价值不在“让运营变慢”，而在防止一个爆款模板把店铺带进高风险区。

## 7. 系统边界结论

调研阶段可以确认：

1. 这个系统可以做成“选品 + 内容测试 + 数据复盘 + 风控提示”的运营工作台。
2. 第一版不应该做自动发布、自动切号、自动采集、自动合规判断。
3. 规则库必须从第一天存在，但它首先是人工核验记录，不是机器裁判。
4. 高风险模板可以保留在模板库里，但必须带风险标签和替代表达建议。
5. 平台规则会变，所以每一条规则都要有最后核验日期。

更具体一点：开发前可以先把规则能力做成“红黄绿灯”。

| 灯号 | 含义 | 动作 |
| --- | --- | --- |
| 绿灯 | 常规低风险内容 | 正常排期 |
| 黄灯 | 有表达、素材或售后风险 | 人工确认后发布 |
| 红灯 | 涉及伪造、侵权、医疗功效、隐私等高风险 | 默认暂停 |
