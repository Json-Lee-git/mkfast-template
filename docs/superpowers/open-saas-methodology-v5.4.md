# 开放式出海工具机会挖掘方法论 V5.4

## 0. 方法论目标

这套方法不是为了找"我现在能不能做"的项目，也不是为了围绕已有项目补关键词。

它的目标是：用 45 个工具词根开放式扫描全球工具型需求，再通过硬筛、冷启动审判、SERP 验证、竞品验证、用户痛点验证、变现小账、**付费意愿预验证**和搜索数据，筛出真正值得验证的出海工具机会。

**V5.2 新增：5 人预验证硬门。** 在写代码之前，必须拿到至少 5 个真实人的使用意愿信号。

**V5.2.1 新增：防 AI 跳过步骤。** SERP 表格、免费替代清单、流量端验证全部强制化。

**V5.2.2 新增：6 条防 AI 偷懒规则。** 品类多样性约束、需求族去重、结果可验性维度、信号质量分级、免费替代三阶段分工、Keyword Planner 不可推翻硬门。

**V5.2.3 新增：防 AI 用叙事替代表格、自行改写检查项、跳过搜索量估算。** 核心原则：任何标注 ★ 的强制表格为空 → 本轮结果不合格。所有候选方向必须列出英文搜索词。不得改写 Section 12.5 检查项原文。

**V5.2.4 新增：四表独立输出规则、SERP 反例警告、文档粘贴最低要求。** Section 10.2 竞品定价表强制表格化。四张核心表（SERP/竞品定价/免费替代/$100小账）必须各自独立，不得合并或叙事替代。Section 27 规定了分段粘贴时必须包含的最小内容集。AI 错误模式扩充至 17 条，自查清单扩充至 18 条。

**V5.3 重大调整：Keyword Planner 前置于预验证。** 搜索数据先校准触达人群——真实案例显示，关键词研究可以提前发现"验证对象说 yes，但搜索词和真实需求错位"的问题。没有搜索量支撑、且没有明确非 SEO 获客路径的需求，不值得投入 1-3 天人肉触达。Section 13 和 14 交换顺序：先跑 KP 确认获客路径存在，再投入预验证确认付费意愿。新增"数据确认门"：公开估算未达到最低数量级 → 直接 Watch/Kill，不进入 KP，更不进入预验证。

**V5.4 收敛修订：规则分层、阈值明确、版本清理。** 修复词根数量错误（51→45，18 核心 + 27 扩展 = 45）、KP 顺序遗留矛盾（错误 15 Section 引用修正）、预验证案例证据校准、预验证评分过刚（拆为硬门/强通过两层）、执行成本过重（10-15 轻量预审 → 3-5 深度四表）、阈值模糊（新增 Section 12.6 阈值解释表）、预验证标准一刀切（新增 Section 14.5 按交付形态分验证标准）、版本引用混乱（Section 编号全校准，文件名 V5.4）。

核心顺序：

```
先开放找机会 → 快速硬筛 → 冷启动快速初判 → 深度冷启动审判
→ SERP / 竞品 / 用户痛点软筛 → 免费替代深度检查 → 变现小账（含流量端）
→ ★ 预验证前 12 条硬门检查 → ★ 数据确认门（公开估算数量级达标？）→ Keyword Planner 验证
→ ★ 5 人预验证（硬门）→ 最终判断 Build / Watch / Kill
```

**正确路径：** 45 个词根 × 多品类开放扩词 → 需求族聚类去重 → 快速硬筛 → 冷启动审定 → 轻量预审 → 3-5 个深度候选做 SERP/竞品/免费替代/变现四表 → **预验证前 12 条硬门检查** → **数据确认门（公开估算未达标 → 直接 Kill/Watch）** → **Keyword Planner（精确搜索量确认）** → **5 人预验证（有效信号 ≥3，≥1 陌生人）** → 判断

**错误路径：** 我已有某个项目 → 围绕它找词 → 找到相关词 → 误以为这是市场机会

**关键防呆：公开搜索量估算（Autocomplete/KE/Ahrefs 免费层）是预验证前最后一道数据门。核心候选词公开估算全部为最低档（几十/月以下）且无明确非 SEO 获客路径 → 直接 Kill/Watch，不进入 KP，更不进入预验证。Keyword Planner 确认获客路径存在后，才投入 1-3 天人肉预验证。SERP 必须实际看 Google 前 10 名。$100 小账必须从搜索量倒推流量。任何 ★ 强制表格为空 → 本轮结果不合格，不继续。任何检查项被自行改写 → 不合格。四张核心表（SERP/竞品定价/免费替代/$100小账）必须各自独立输出，不得合并为一张表或融合为叙事段落。**

## 1. 底层原则

### 1.1 有搜索量，不等于有机会

必须区分：
- 有搜索量 ≠ 有商业机会
- 有 CPC ≠ 你能赚钱
- 有竞品 ≠ 你能切进去
- 有痛点 ≠ 用户会用你的词搜索
- 有页面可写 ≠ 页面有价值
- 能开发 ≠ 该开发

一个机会成立，必须回答：

| 问题 | 验证方式 |
|------|---------|
| 用户在搜什么？ | SERP 分析 |
| 用户为什么搜？ | 搜索意图判断 |
| 用户现在用什么？ | 竞品分析 |
| 用户现在付多少钱？ | 竞品定价 |
| 用户骂竞品什么？ | 四路搜索法 |
| 竞品为什么能赚钱？ | CPC 反推 + 定价页 |
| 我们冷启动能不能进入？ | 冷启动审判 |
| **有真人愿意用我们的产品吗？** | **5 人预验证（V5.2 新增）** |
| 最小交付形态是什么？ | 交付形态判断 |
| 用户来了以后钱怎么赚？ | 变现路径 |

### 1.2 SEO 是验证和获客方式，不是母方向

SEO / GEO / AI Visibility 只是一个可能品类，不是全部市场。

母方向应该来自：用户任务、工具动作、平台变化、政策变化、工作流变化、新技术变化、商业流程变化。

SEO 的作用是：
- 验证需求是否有搜索入口
- 判断新站是否有机会拿流量
- 决定做工具页、对比页、模板页、报告页还是内容页
- 降低早期获客成本

我们找的不是"SEO 工具机会"，而是：**可以通过搜索流量验证和承接的全球工具型机会。**

## 2. 总执行流程（V5.4）

先数据，后人肉。先确认有人搜，再确认有人买。

```
1.  选择 5–8 个大品类（必须跨 ≥5 类用户任务场景，禁止全选 SEO/AI/Marketing 相邻品类）
2.  用 45 个词根开放扩词 → 生成 100–300 个原始候选词
2.5 ★ 需求族聚类去重：同一用户任务在不同平台/修饰词下只算一个需求族，每族最多保留 3 个代表词（V5.2.2 新增）
3.  快速硬筛（数据敏感度 / 意图类型 / 合规 / 免费替代常识三问）
4.  保留 30–50 个低风险候选
5.  冷启动快速初判（数据敏感度 / 上传要求 / 账号授权 / 信任门槛 / ★结果可验性）
6.  保留 20–25 个候选
7.  深度冷启动审判（只展开中高风险项）
8.  缩小到 10–15 个轻量候选
9.  SERP / 竞品 / 用户骂点轻量预审（只判断是否值得深挖）
10. 只选 3–5 个深度候选，完整做竞品定价、免费替代、用户痛点验证
11. 对 3–5 个深度候选做免费替代深度检查（必须列具体工具名和覆盖场景%）
12. 对 3–5 个深度候选算初步变现小账（月入 $100 需要多少流量/成交 — 必须含流量端验证）
12.5 ★ 预验证前 12 条硬门检查 + 数据确认门（只对 3–5 个深度候选执行，全部通过才能进入 KP）
13. ★ Keyword Planner 验证 — 从深度候选中只选最多 3 个方向（每个方向最多 3–5 个词），确认获客路径存在（V5.3 前置）
14. ★ 付费意愿预验证（硬门）— 至少 5 个真人信号，其中 ≥3 个有效信号，≥1 个来自陌生人（V5.2.2 强化，V5.3 后置于 KP）
15. 根据 KP + 预验证结果做最终状态判断：Kill / Watch / Build Page / Build Tool / Build Template / Build Report / SaaS Later
★ 预验证前数据确认门：公开估算全部为最低档（几十/月以下）且无非 SEO 获客路径 → 直接 Kill/Watch，不进入 KP（V5.3 新增）
```

## 5. 候选词生成公式

**★ V5.2.3 硬约束：所有候选方向必须列出英文搜索词。用户搜的是英文，不是中文。"Cricut SVG 上传失败检查"不是搜索词——"svg won't upload to cricut""cricut design space svg fix""cricut svg converter"才是。全程用中文描述性名称而不给英文搜索词 → 不合格。**

### 5.1 基础公式
`[品类] + [词根]`
例：invoice generator · csv cleaner · resume checker · etsy fee calculator

### 5.2 平台公式
`[平台] + [对象] + [词根]`
例：shopify product description generator · etsy tag generator · amazon fba calculator

### 5.3 用户公式
`[词根] + for + [用户]`
例：invoice generator for freelancers · resume checker for nurses · pricing calculator for agencies

### 5.4 批量公式
`bulk/batch + [对象] + [词根]`
例：bulk image resizer · bulk product description generator · batch pdf converter

### 5.5 替代品公式
`[竞品] alternatives` · `[竞品] vs [竞品]` · `better than [竞品]` · `[竞品] pricing` · `[竞品] too expensive`

### 5.6 新变化公式
`[new platform / new policy / new tech] + [词根]`
例：tiktok shop fee calculator · chatgpt product feed checker · ai image detector

### 5.7 需求族聚类去重 ★ V5.2.2 新增

扩词后容易产生大量"看起来不同、实际上是同一件事"的词。例如：
- AI caption generator / Instagram caption generator / TikTok caption generator / LinkedIn post generator

这四个词属于同一个需求族（"自动生成社媒配文"），不能算 4 个独立机会。

**去重规则：**

1. 所有候选词按"用户任务"聚类——用户想完成的是同一件事吗？
2. 每个需求族最多保留 3 个代表词：一个主词（最大搜索量）、一个长尾词（更精准）、一个变现词（含 buying intent）
3. 在输出中必须标注：该候选属于哪个需求族？该族共含多少个原始词？

**需求族定义：用户任务相同 + 输出类型相同 + 使用场景相同。只有平台不同 → 同一需求族。**

去重后的候选词数量才是真实的机会数量。100 个词缩成 30 个需求族是正常的。

## 6. 快速硬筛

开放扩词后，先做快速硬筛，不要马上查 SERP 和竞品。

目标：快速识别那些数据可能好看、但天然不适合冷启动的假机会。

### 6.1 数据敏感度检查

```
风险 = 数据类型 × 上传方式 × 是否即时处理 × 结果错误后果
```

| 数据类型 | 信任门槛 | 冷启动难度 | 示例 |
|---------|---------|-----------|------|
| 公开信息 | 低 | 低 | TikTok fee calculator, barcode scanner |
| 用户自填非敏感数据 | 低 | 低 | invoice generator, pricing calculator |
| 普通文档 | 中 | 中 | resume checker, PDF merger |
| 财务文档 | 高 | 极高 | bank statement, tax form, invoice scanner |
| 身份/法律文档 | 极高 | 致命 | passport scanner, visa checker, legal contract |
| 医疗数据 | 极高 | 致命 | symptom checker, medical report analyzer |

高敏感数据规则：用户需要上传或输入银行流水、税务文件、身份证件、护照、医疗记录、法律合同、工资单、贷款资料、商业机密 → 自动进入高风险。

继续追问：冷启动 6 个月内能否建立信任？是否能本地处理、不上传？是否能开源？没有可信路径 → 直接 Watch 或 Kill。

### 6.2 搜索意图类型检查

| 意图类型 | 用户状态 | 适合承接 | 不适合承接 |
|---------|---------|---------|-----------|
| 即时解决型 | 我现在要结果 | 工具、计算器、转换器 | 纯内容页、fake-door |
| 探索研究型 | 我在比较方案 | best、alternatives、pricing、review | 强推单一工具 |
| 学习了解型 | 我想理解概念 | guide、tutorial、glossary | 直接付费工具 |
| 购买决策型 | 我准备选工具 | 对比页、评价页、affiliate | 空泛内容 |

硬筛阶段词面初判（不看 SERP）：
- 词含 converter/calculator/generator/checker/formatter/resizer → 倾向即时解决型
- 词含 best/pricing/review/alternatives/vs/comparison → 倾向探索研究型/购买决策型
- 词含 how to/guide/tutorial/what is → 倾向学习了解型

### 6.3 合规和平台风险

快速排除：违法下载、版权侵权、平台明确禁止抓取/自动化、医疗诊断、法律结论、税务结论、投资建议、身份验证、高风险金融建议、成人/赌博/武器/药品。

这些方向没有明确合规路径，直接 Kill 或 Watch。

### 6.4 免费替代常识三问

硬筛阶段不查 SERP，只做常识级判断：

1. 这个任务是否已经被操作系统/平台/浏览器原生功能免费解决？
   - 例：截图、基础 PDF 查看、图片预览、简单二维码扫描
2. 这个任务类型是否长期存在大量知名免费工具？
   - 例：图片压缩、PDF 合并、二维码生成、单位换算、基础 JSON formatter
3. 这个方向是否属于"免费工具用户预期极强"的品类？
   - 例：普通格式转换、基础下载、基础图片处理、基础文本处理

任一条明确为是 → 标记为"免费替代高风险"，但**不得在此阶段直接 Kill**。只有在免费替代深度检查（Section 11）确认完全覆盖后才 Kill。早期只标记风险，不执行否决。

**★ V5.2.2 免费替代三阶段分工：**

| 阶段 | 检查目的 | 处理方式 |
|------|---------|---------|
| 快速硬筛（Section 6.4）| 标记明显无差异化的方向 | 只标记风险，不直接 Kill，除非完全被系统原生功能覆盖 |
| 深度检查（Section 11）| 判断免费替代覆盖多少真实场景 | 必须列具体工具、覆盖比例、未覆盖场景，满足条件才 Kill |
| 变现小账（Section 12）| 判断用户为什么愿意付费 | 必须说明付费突破点——免费工具做不到的到底是什么 |

核心原则：**有免费替代不等于不能做。免费替代覆盖 90% 核心场景 + 用户无切换成本 + 用户无明显抱怨 → 才危险。**

## 7. 冷启动快速初判

快速硬筛后，对 30–50 个低风险候选做冷启动快速初判。

目的：用更低成本识别"从 0 很难进入"的方向，把候选池缩小到 20–25 个。

| 维度 | 打分 |
|------|------|
| 数据敏感度 | 低 / 中 / 高 |
| 上传要求 | 无 / 有 |
| 账号授权 | 无 / 有 |
| 信任门槛 | 低 / 中 / 高 |
| **★ 结果可验性** | **高 / 中 / 低** |
| 初判结论 | 通过 / 标记 / Watch |

**★ V5.2.2 新增：结果可验性。** 用户是否能在 30 秒内判断工具输出是否正确/有用。

| 可验性 | 定义 | 示例 | 冷启动影响 |
|--------|------|------|-----------|
| 高 | 结果立刻可判断对错/好坏 | JSON formatter、图片压缩、汇率换算、费用计算器 | 冷启动友好，用户不需要信任你 |
| 中 | 需要一定背景知识才能判断 | SEO audit、代码生成、简历评分、语法检查 | 需要样本展示或免费试用降低门槛 |
| 低 | 结果主观或需要长期验证 | AI business idea generator、投资建议、法律合同检查、医疗建议 | 需要强信任机制，冷启动极难，优先 Watch/Kill |

判断：数据敏感度低 + 无上传 + 无账号授权 + 信任门槛低 + 结果可验性高 → 低冷启动风险，可继续。任一项为中 → 标记，进入深度审判。两项以上为高 → Watch。

## 8. 深度冷启动审判

只对标记项展开。目标：杀掉那些表面有需求，但从 0 没法进入的机会。

冷启动状态：无品牌、无信任、无邮件列表、无 SEO 权重、无社媒粉丝、无行业关系、无用户评价、无合规认证。

### 8.1 冷启动高风险类型

需要上传高敏感数据 · 需要行业资质 · 需要深专业判断 · 需要长期数据积累 · 需要网络效应 · 需要企业销售 · 需要合规认证 · 需要强品牌信任

### 8.2 审判三问

1. **数据敏感度为中/高时：** 为什么敏感？用户输入或上传了什么？错误结果会造成什么后果？能否避免上传？能否本地处理？
2. **需要上传文件/私密内容/账号授权时：** 用户为什么会信任我们？有没有不上传的替代路径？上传是否是刚需？
3. **信任门槛为中/高时：** 今天上线，用户为什么信我们？竞品建立信任用了多久？竞品有没有认证、review、案例、品牌？6 个月内能否建立可见信任？

判断：
- 有明确低信任替代路径 → 继续
- 信任路径不清楚 → Watch
- 信任路径明显不可行 → Kill

**重要：任何维度标记为"中"时，必须展开说明——为什么是中？哪部分中？有没有降为"低"的替代路径？不允许仅标注"中"而不展开。**

## 9. SERP 软筛

只有通过快速硬筛和冷启动审判的方向，才进入 SERP 软筛。

### 9.1 看前 10 名

记录：前 10 名是谁？是工具页还是内容页？有没有官方文档？有没有 Reddit/G2/Capterra？有没有 pricing 页面？有没有新站或小站？有没有强站垄断？

**每个候选方向必须输出以下 SERP 表格（不可跳过，不可用叙事替代）：**

```
| 候选词（英文） | 搜索量估算 | 前5名构成（具体网站名） | 有小站？ | 强站垄断？ | SERP判断 |
|--------|-----------|----------|---------|-----------|---------|
| xxx generator | ~X00/月 | tool.com, blog.com, official.com, reddit.com, youtube.com | 是/否 | 是/否 | 可进/困难/不可进 |
```

**只用搜索量数字替代 SERP 截图判断 → 不合格。写"官方帮助、教程、SVG repair/converter"这种叙事而不填表格 → 不合格。必须实际打开 Google 看前 10 名是谁，必须填表，必须写具体网站名。**

**★ 反例警告：以下写法均不合格：**
- ❌ "工具页 + 竞品页 + Reddit" — 这不是具体网站名，这是类型描述
- ❌ "官方帮助页面 + 第三方博客 + 论坛" — 同上
- ❌ "mostly official docs and some blog posts" — 同上
- ✅ "cricut.com, designbundles.net, reddit.com/r/cricut, sofontsy.com, youtube.com" — 这才是具体网站名

### 9.2 SERP 决策矩阵

| SERP 现象 | 判断 |
|-----------|------|
| 前 3 全是工具页 | 用户要即时工具，纯内容页弱 |
| 前 3 有 best/pricing/alternatives | 购买决策页机会较强 |
| 前 5 全是强站 | 新站短期 SEO 难 |
| 内容页全是工具站自己的 blog | 竞品已用内容截流，新站难竞争 |
| 有独立小内容站排前 3 | Build Page 机会更真实 |
| 有免费工具排前面 | 必须评估免费是否足够好 |
| 全是官方文档 | 用户更信官方，第三方工具机会谨慎 |
| 全是低质量垃圾站 | 可能有机会，也可能是低价值词 |

### 9.3 Reddit / G2 / Capterra 前排的二分判断

**解释 A：内容空白**
前 3 有 Reddit/G2/Capterra，第 4–10 有独立对比页/独立评价页/小内容站 → 市场缺高质量内容，独立页面有机会。结论：可继续评估。

**解释 B：信任外移**
前 3 有 Reddit/G2/Capterra，第 4–10 全是工具官网，没有独立评价页存活 → 用户不信任工具站自说自话。结论：需要真实测试、透明评测、用户访谈、社区资产，或者放弃。

### 9.4 小站/低权重站操作性定义

至少满足以下 2 条可视为小站：非知名品牌 · 非头部 SaaS 官网 · 非大型媒体/.gov/.edu/Wikipedia · 域名较新 · 页面是独立内容站或小工具站 · 无明显大量外链 · 内容质量普通但仍靠前。

## 12. 变现路径与 $100/月小账

每个方向必须明确回答：这个方向到底怎么赚钱？

### 12.1 变现路径类型

Affiliate · Lead Gen · Sponsored Listing · Display Ads · Freemium Tool · Pay-per-use · One-time Purchase · Paid Template · Paid Report · SaaS Subscription Later · No Clear Monetization

### 12.2 每个方向必须算小账

至少估算：首选变现路径？用户付费动作？客单价？预计转化率？月入 $100 需要多少流量/提交/付费？这个流量规模现实吗？

| 变现类型 | 客单价 | 月入$100 所需 | 关键假设 |
|---------|--------|-------------|---------|
| Affiliate | 佣金 $20 | 成交 5 单/月 | 点击→成交 2%，页面 CTR 20% → 需 1250 次/月 |
| One-time Template | $9 | 成交 12 单/月 | 访问→购买 2% → 需 600 次/月 |
| Pay-per-use Tool | $5/次 | 付费 20 次/月 | 试用→付费 5% → 需 400 次/月 |
| Sponsored Listing | $100/位 | 1 个赞助商 | 页面必须有稳定流量 |

没有清晰变现路径 → 不能进入 Build。

### 12.3 流量端验证（不可跳过）

只算"需要多少单"不算流量 → 小账不完整。必须补上：

```
目标词月搜索量估算 → 新站排前10预计拿到3–5%点击 → 月流量估算
月流量 × 页面转化率（模板/工具通常1–3%）→ 月付费单数
月付费单数 × 客单价 → 月收入
```

用这个链反推：核心词搜索量只有 100/月 → 5% 点击 = 5 次访问 → 2% 转化 = 0.1 单/月 → $9 模板 = $0.9/月。$100/月在这个流量规模下完全不现实。

**如果核心候选词月搜索量 < 500，必须在变现小账中明确标注"流量不足以支撑 $100/月"，并说明获取流量的非 SEO 路径是什么。**

### 12.4 四张核心表独立输出规则 ★ V5.2.4 新增

以下四张表是方法论的核心结构化数据，**每张表必须独立输出，不得合并**：

| 表 | 位置 | 列数 |
|---|------|------|
| SERP 前 10 名分析表 | Section 9 | 6 列（候选词/搜索量估算/前5名构成/有小站？/强站垄断？/SERP判断） |
| 竞品定价表 | Section 10.2 | 8 列（竞品名称/免费额度/最低套餐/中间套餐/团队套餐/按量价格/主要卖点/用户抱怨/切口） |
| 免费替代清单 | Section 11 | 3 列（免费替代名称/覆盖场景%/用户抱怨） |

**AI 常犯错误：把四张表"融合"成一张综合表，或者把表的内容写成叙事段落。**
- ❌ 把 SERP 分析、竞品信息、免费替代、变现数据全塞进一张大表 → 不合格
- ❌ 把竞品定价写成"竞品 A 免费版够用，竞品 B $9/月起"叙事 → 不合格
- ❌ 把 SERP 表格和竞品定价表合并为一张"市场分析表" → 不合格
- ✅ 四张表各自独立、各自完整、各自按原格式输出

**每张表服务于不同的判断：** SERP 表判断能否进入搜索流；竞品定价表判断竞品是否赚钱和我们的切口；免费替代清单判断是否已有足够好的免费方案；$100 小账判断变现是否现实。合并表会模糊这些独立判断。

## 13. Keyword Planner 验证 ★ V5.3 前置于预验证

Keyword Planner 不是探索工具，是获客路径确认。**在投入 1-3 天人肉预验证之前，先用 KP 确认搜索量是否支撑获客假设。**

**只有满足以下所有条件，才跑词：**
- 快速硬筛通过
- 冷启动快速初判通过
- 深度冷启动审判通过
- SERP 初步可做
- 竞品和痛点有迹象
- 变现路径初步算得通
- **预验证前 12 条硬门检查 + 数据确认门通过（Section 12.5）**

每轮最多选 3 个方向，每个方向最多给 3–5 个词。

**★ V5.2.2 硬约束（V5.3 修订）：Keyword Planner 验证获客路径，但不得推翻冷启动审判、免费替代深度检查、一票否决的硬门判断。若这些硬门未通过，即使 KP 显示高搜索量/高 CPC，也不能进入 Build。只能 Watch 或 Kill。**

**★ V5.2.3/V5.3 重要澄清：Keyword Planner（Section 13）≠ 公开搜索量估算（Section 12.5 第 9 条）。** 公开估算在 12.5 阶段用免费工具完成，给出数量级。KP 需要 Google Ads 账号，给出精确搜索量和 CPC。两者缺一不可——公开估算给方向判断，KP 给精确确认。

**★ V5.3 新增：KP 在预验证之前的目的。** 不是"因为搜索数据比人重要"，而是因为真实案例反复说明：人工访谈可能验证了错误表述、错误人群或错误搜索词；关键词研究可以提前发现目标词与真实搜索词错位。**KP 在前，是为了让你在找 5 个陌生人之前，先确认你找的是正确的那 5 个陌生人、验证的是正确的获客入口。**

KP 可能出现长尾词报零但真实搜索存在的情况。处理方法：如果 KP 报零/横杠，但 Autocomplete + Related Searches + Reddit 有明确信号 → 不要直接 Kill，回到 Serper.dev 或手动 Google 交叉验证。确认需求存在后，用非 SEO 获客路径（Reddit/社区/Discord）替代 SEO 假设，重新评估获客成本。

### 13.1 搜索量判断

| 搜索量 | 判断 |
|--------|------|
| 横杠/0 | 交叉验证 Autocomplete + Reddit。无其他信号 → 不成立。有其他信号 → 标记"KP低估"，继续但必须用非 SEO 获客 |
| 10–100 | 小词，只有高 CPC 或强痛点才保留 |
| 100–1000 | 可做长尾 |
| 1000–1 万 | 较强 |
| 1 万+ | 大词，通常竞争高 |

### 13.2 CPC 判断

CPC 代表广告主愿意为点击付费，不等于你一定能赚钱。

| CPC | 判断 |
|-----|------|
| 无 CPC | 商业意图弱 |
| 低 CPC | 可能是免费需求或信息词 |
| 中 CPC | 可继续看 |
| 高 CPC | 竞品可能有钱，但必须做 CPC 反推 |

### 13.3 CPC 反推检查

看到高 CPC，必须问：谁在为这个词出价？他们靠什么覆盖获客成本？他们 LTV 是多少？他们是否有品牌信任？我是否能拿到同样质量的 SEO 流量？我能不能通过 affiliate/lead/report/tool signup 转化？

**高 CPC = 竞品能赚钱。不等于新站能赚钱。**

特别注意：10–100 搜索量 + 极高 CPC → 极窄的高价值人群被精准竞价，不一定是适合新站的大众机会。

## 14. 付费意愿预验证（硬门）★ V5.2 新增，V5.3 后置于 KP

> **这是 V5.2 的核心新增项。在写任何代码之前，必须拿到至少 5 个真实人的使用意愿信号。V5.3 调整：KP 确认获客路径存在后，再投入人肉预验证。数据告诉你"有人在搜"，预验证告诉你"有人愿意为你付费"——两个都通过才进入 Build。**

### 14.1 硬门定义

**在步骤 13（Keyword Planner 确认获客路径存在）之后、最终 Build 决策之前，必须通过 5 人预验证，否则不进 Build。**

不满足 → 退回 Watch 或 Kill。

### 14.2 验证流程

#### 第一步：最小 Landing Page（30 分钟）

针对候选方向，使用 `src/pages/validate/` 模板搭一个单页：
- 标题：一句话说清产品做什么
- 副标题：一句话说清解决什么痛点
- 一个邮箱输入框 + "Get early access" 按钮
- 3 条价值主张
- 页脚诚实标注："This is a validation page — the product is not built yet."

后端使用 Formspree 免费版收邮件（50 封/月），零后端代码。

#### 第二步：主动触达（1-3 天）

找到正在讨论这个痛点的人，发私信：

| 渠道 | 搜索方式 |
|------|---------|
| Reddit | Google 搜 `site:reddit.com "[痛点关键词]"` |
| Twitter/X | 搜 `"[工具类别] sucks"` `"[工具类别] too expensive"` |
| G2/Capterra | 找竞品页面，翻 1-3 星差评 |
| YouTube | 搜 `"[问题] tutorial"` — 在看教程的人正被痛点折磨 |

私信模板：

> "Hey — I saw your comment about [他们提到的具体痛点]. I'm exploring whether to build a tool to [一句话解决方案]. Nothing built yet — just validating. If I make it, want me to let you know? [验证页链接]"

关键规则：
- 引用他们自己的话。绝不复制粘贴同一条消息。
- 坦承产品还没做。诚实就是信任机制。
- 不用任何营销语言。像真人私信另一个真人。

#### 第三步：收集和计分

| 优先级 | 信号类型 | 权重 | 是否算"有效信号" |
|--------|---------|------|-----------------|
| 最强 | 留邮箱 + 回复了后续邮件、确认了痛点 | 1.0 | ✅ 有效 |
| 强 | 愿意支付小额预售/定金 | 1.0 | ✅ 强有效 |
| 强 | 愿意介绍同类用户 | 1.0 | ✅ 强有效 |
| 中等 | 留邮箱但未回复后续邮件 | 0.5 | ✅ 弱有效 |
| 中等 | 愿意预约试用/演示 | 0.5 | ✅ 有效 |
| 中等 | 愿意发真实文件/真实场景测试 | 0.5 | ✅ 有效 |
| 补充 | 私信回复"我会用"但未留邮箱 | 0.25 | ❌ 不算有效 |
| 无效 | 只说"挺有意思""good luck" | 0 | ❌ 不算 |
| 无效 | 打开页面即跳出、无任何互动 | 0 | ❌ 不算 |
| 污染 | 来自朋友/同事/熟人的鼓励 | 不计分 | ❌ 排除 |

**★ V5.2.2 硬门强化：5 个真人信号中，必须包含 ≥3 个"有效信号"（有效/强有效），且 ≥1 个来自陌生人或弱关系用户。全部来自朋友鼓励 → 不算通过，不计分。**

"陌生人"定义：你在触达之前不认识对方，对方也不认识你。Reddit 评论区回复、Twitter 公开讨论、Indie Hackers 帖子回复均算陌生人。

#### 第四步：判断

先判断硬门，再判断强度。硬门用于决定能不能进入最终状态判断；得分用于判断信号强弱，避免把 5 个弱互动误判成强需求。

| 条件 | 判定 | 行动 |
|------|------|------|
| ≥5 个真实触达回应，**≥3 个有效信号，≥1 个陌生人** | **硬门通过** | 进入最终状态判断（GO 条件 + 一票否决 → Build/Watch/Kill） |
| 硬门通过，且得分 ≥5.0 分，≥2 个渠道，≥3 封邮件 | **强通过** | 可提高 Build 优先级 |
| 得分 2.0–4.75 分，或有效信号 <3，或全来自熟人 | **Watch** | 记录阻塞原因，30 天后调整方式重试 |
| <2.0 分 | **Kill** | 痛点不够痛，放弃此方向 |

### 14.3 为什么简陋页面不是问题

- 简陋页面 + 有人留邮箱 = 痛点足够强，用户愿意"赌一下"
- 精美页面 + 无人留邮箱 = 优化转化率不解决根本问题
- 私信本身在解决初始信任——一个真人说"我在做这个"比任何页面设计都管用

### 14.4 为什么不是 50 人

5 不是统计学上的显著样本，而是早期机会验证的最低摩擦门槛：一个人可能是噪音，5 个真实触达回应里有 3 个有效信号，说明痛点至少值得继续判断。这个数字在"有足够真实信号"和"不浪费开发时间"之间取得平衡。

### 14.5 按交付形态区分验证标准 ★ V5.4 新增

5 人预验证的核心逻辑对 Build Tool / SaaS Later 完全适用："有人愿意留邮箱 = 有人愿意用"是清晰的验证路径。但对其他交付形态，用户不会为不存在的东西"付费"或"留邮箱"，验证信号类型需要调整。

| 交付形态 | 核心验证问题 | 有效信号类型 | 最低通过标准 |
|---------|-------------|------------|------------|
| **Build Tool** | 用户是否愿意留邮箱等产品上线？ | 留邮箱、预约试用、小额预售、介绍同类用户 | 硬门：≥5 回应 + ≥3 有效 + ≥1 陌生人 |
| **SaaS Later** | 同上，但更关注持续使用意愿 | 留邮箱 + 回复后续邮件确认使用场景 | 同上 |
| **Build Page** | 用户是否会点击/收藏/参考这个页面？ | 点击行为（如果有 Demo 页）、收藏、分享、竞品跳转 | 硬门同等要求。如无邮箱收集条件，可用"≥10 个真实点击+停留>30s"替代，但需标注"邮箱未验证" |
| **Build Template** | 用户是否愿意付费下载模板？ | 留邮箱、小额预售（$1-3 定金）、发真实文件请求定制 | 硬门同等要求。"我会用"不算有效信号——模板需要付钱才算 |
| **Build Report** | 用户是否愿意提交信息换取报告？ | 提交真实数据、留邮箱、小额预售 | 硬门同等要求。提交数据比留邮箱更有说服力 |

**所有交付形态通用规则：**
- 必须 ≥1 个陌生人信号（排除熟人鼓励）
- 触达中必须引用对方原话（证明你找到了真实痛点场景）
- 验证页必须诚实标注"This is a validation page — the product is not built yet."

**降级说明：** 如果候选方向在 KP 阶段就判断为 Build Page / affiliate 方向（不是 Build Tool），在预验证阶段不强制要求邮箱收集。但必须在输出中明确标注"本次验证未收集邮箱，改用 [替代信号类型]，信号强度低于邮箱验证"。

## 16. 一票否决机制

一票否决是硬门。满足任一条，不能 GO。

**每个候选方向必须逐条过以下 7 条否决清单，明确标注"触发"或"通过"（不可跳过）：**

```
候选方向：___________

☐ 1. 高敏感数据否决 — 触发/通过 — 理由：___
☐ 2. 即时意图否决 — 触发/通过 — 理由：___
☐ 3. 免费替代否决 — 触发/通过 — 理由：___
☐ 4. 竞品护城河否决 — 触发/通过 — 理由：___
☐ 5. SERP 强锁死否决 — 触发/通过 — 理由：___
☐ 6. 高风险合规否决 — 触发/通过 — 理由：___
☐ 7. 预验证否决（V5.2）— 触发/通过 — 理由：___

任意一条触发 → 不能 GO。全部通过 → 进入 GO 条件检查。
```

| 否决条件 | 触发条件 | 结果 |
|---------|---------|------|
| 高敏感数据否决 | 数据敏感度高 + 冷启动 6 个月无法建立信任 + 无法本地处理 | Watch/Kill |
| 即时意图否决 | 搜索意图是即时解决型但只能做 Build Page | Watch/Kill |
| 免费替代否决 | ≥2 个免费工具足够好 + 覆盖核心场景 + 用户无不满 | Kill/Watch |
| 竞品护城河否决 | 前 3 竞品有不可复制护城河（合规认证、多年数据、独家合作等） | Watch/Kill |
| SERP 强锁死否决 | 前 5 全是强站 + 无独立小站存活 + 需 12 个月以上 | Watch |
| 高风险合规否决 | 医疗/法律/金融/身份/税务 + 需专业资质 + 无法承担准确性责任 | Kill/Watch |
| **预验证否决（V5.2 新增）** | **付费意愿预验证 <2.0 分** | **Kill** |

## 20. 状态体系

最终状态：

- **Kill** — 不做，不抢救。只有市场发生重大变化才复查。
- **Watch** — 暂不做，必须有原因、优先级、激活条件和复查日期。
- **Build Page** — 做页面矩阵。
- **Build Tool** — 做轻工具。
- **Build Template** — 卖模板。
- **Build Report** — 卖报告或半自动审计。
- **SaaS Later** — 不是当前阶段，除非已有行为信号。

26. **★ Keyword Planner 词列表** — 建议跑的 3–5 个词（最多 3 个方向）
27. **★ Keyword Planner 结果与获客路径确认** — 搜索量/CPC 确认后的判断，是否因 KP 结果调整获客假设？（注意：KP 不得推翻冷启动/免费替代硬门。若 KP 报零但有 Autocomplete/Reddit 信号 → 标记"KP 低估"，用非 SEO 获客路径替代）
28. **★ 付费意愿预验证结果** — 收集了多少信号？有效信号几个？几个来自陌生人？得分？≥2 个渠道？≥3 封邮件？通过/不通过？
29. 当前状态：Kill/Watch/Build
30. Watch 机制（如为 Watch）

## 23. 每轮执行方式

每轮开放式挖掘：

1. 选择 5–8 个大品类
2. 每个品类套 18 个高频词根
3. 生成 100–300 个候选词
4. 快速硬筛
5. 保留 30–50 个低风险候选
6. 冷启动快速初判
7. 保留 20–25 个候选
8. 深度冷启动审判
9. 缩小到 10–15 个候选
10. **轻量预审：** SERP / 竞品 / 用户骂点快速过（只判断是否值得深挖，不填完整四表）
11. **选 3–5 个深度候选：** 对深度候选做完整四表（SERP 表 / 竞品定价表 / 免费替代清单 / $100 小账）
12. **★ 预验证前 12 条硬门检查 + 数据确认门（Section 12.5）— 只对 3–5 个深度候选执行 ★**
13. **★ 只从深度候选中选最多 3 个方向跑 Keyword Planner（每个方向最多 3–5 个词）★**
14. **付费意愿预验证（硬门）— 至少 5 个信号 ★**
15. 根据 KP + 预验证结果进入最终状态判断

**关键：不要在 10–15 个候选上都做完整四表。** 10–15 阶段只做轻量判断，选出最有希望的 3–5 个才投入深度分析。这能防止 AI 因为工作量过大而"看起来填了表"。不要一下子跑几十个词。不要把 Keyword Planner 当探索工具。**先确认有人搜（KP），再确认有人买（预验证），最后写代码。**

## 25. 案例校准

### 25.1 Bank Statement Converter

- 数据层面：有搜索量（1000–1 万），竞品存在，用户痛点存在，付费锚点存在。上半场通过。
- 冷启动层面：银行流水是高敏感数据，搜索意图是即时解决型，Build Tool 有隐私和准确率压力，新站缺少品牌和信任。
- **最终状态：Watch（High）**。搜索机会成立，但冷启动机会不成立。

### 25.2 TikTok Shop Fee Calculator

- 数据层面：有搜索，用户输入公开规则和自填数据，工具能即时输出，敏感度低，冷启动信任门槛低。
- 风险：词簇可能不厚，免费工具可能存在，平台费率需维护。
- **最终状态：Build Tool Candidate / Watch。** 未必是大机会，但比 Bank Statement 更适合冷启动测试。

### 25.3 Product Feed Validator

- 功能逻辑成立，但搜索词簇弱，Keyword Planner 数据不足，CPC 和付费锚点不强。

### 25.4 PDF Table Extractor

- 有一定搜索需求但趋势弱，商业意图不够强，泛 PDF 工具免费替代多。
- **最终状态：Watch（Medium/Low）。** 可作为垂直方向的支撑功能，不适合独立主项目优先做。

## 26. AI 执行常见错误与防呆设计 ★ V5.2.1 新增，V5.4 维持 18 条

> **以下错误在任何 LLM（GPT、Claude、Gemini、DeepSeek 等）执行本方法论时反复出现。这些不是某个模型的缺陷，而是所有 LLM 的共性——省 Token、走叙事不走表格、改写规则而不是逐字执行。执行者必须在每轮结束后对照此清单自查。**

### 错误 1：跳过 SERP 实际查看

**表现：** 搜了 Reddit、GitHub、官方文档、竞品 blog，引了一堆链接，但没有实际打开 Google 看任何一个候选词的前 10 名。

**为什么是错的：** Reddit 帖子、GitHub 项目和官方文档告诉你"需求存在"，但 SERP 告诉你"新站能不能进去"。两个是不同的信息。

**正确做法：** 每个方向至少挑 2 个核心候选词，打开 Google（无痕窗口），看前 10 名是谁。填 Section 9 的 SERP 表格。

### 错误 2：免费替代只说程度，不给名字

**表现：** "免费替代压力中等""有 GitHub/开源工具但体验碎"——没有列出具体工具名。

**为什么是错的：** 不说名字 = 没有真正查过。两个看起来差不多的方向，一个可能被 3 个高质量免费工具覆盖 90% 场景，一个可能只有 1 个半成品开源项目覆盖 30%。只有列出具体名字和覆盖范围，才能判断。

**正确做法：** 填 Section 11 的免费替代清单表——每行一个工具名 + 覆盖场景% + 用户抱怨引用。

### 错误 3：变现小账只算"需要多少单"，不算"需要多少流量"

**表现：** 写了"$9 × 12 单/月"就完了。

**为什么是错的：** 如果核心词月搜索量只有 100，"12 单/月"根本不可能。变现小账必须有流量端才能判断是否现实。

**正确做法：** 按 Section 12.3 的链路反推——搜索量 → 流量 → 转化 → 收入。核心词搜索量 < 500 的，必须说明流量从哪来。

### 错误 4："中"不展开

**表现：** 数据敏感度标"低到中"、免费替代标"中高"，但不说为什么。

**为什么是错的：** "中"是一个灰度地带——可能接近"低"，也可能接近"高"。不展开就无法判断。

**正确做法：** 按 Section 8 要求——任何"中"必须展开说明：哪部分中？为什么不是低？有没有降为低的替代路径？

### 错误 5：一票否决清单没逐条过

**表现：** 给了综合判断、给了优先级排名，但没有逐条过 7 条否决条件。

**为什么是错的：** 一条触发就是 Kill/Watch，跟你综合排名第几无关。一个方向可以排在第一名，但如果触发"免费替代否决"，它就是不能 GO。

**正确做法：** 按 Section 16 的 checkbox 格式，三个候选各过一遍 7 条否决。逐条标注"触发"或"通过"。

### 错误 6：开发者工具默认付费意愿正常

**表现：** 把开发者工具当成和卖家工具一样对待，用同样的转化率估算。

**为什么是错的：** 开发者是所有人群中付费意愿最低的群体之一。GitHub 上几千 star 的项目，付费转化率可能不到 0.1%。卖家工具上"$9 模板卖 12 单"是合理的——开发者工具上同样的假设需要更充分的证据。

**正确做法：** 按 Section 4.10 注意——开发者工具必须额外验证竞品付费锚点。竞品全是开源/免费、没有 pricing page → 不做。

### 错误 7：在没有搜索量估算的情况下排优先级

**表现：** 综合评分、置信度分析都做完了，但没有一个候选词的搜索量估算。

**为什么是错的：** 你可以做一个世界上最完美的工具，但如果没人搜、搜的量不足以支撑获客，它就是一个零流量的完美工具。

**正确做法：** 在进入预验证之前（Section 12.5 第 9 条），至少用公开数据（Ahrefs/Semrush 免费层、Keywords Everywhere、Google 自动补全和相关搜索）估算核心候选词的月搜索量。不需要精确到个位数，但必须有一个数量级判断（几十/几百/几千/几万）。

### 错误 8：品类选品偏差 ★ V5.2.2 新增

**表现：** 选的 5–8 个品类全部来自 SEO / AI / Marketing / 文档处理等相邻领域。

**为什么是错的：** 这等于在自己熟悉的方向里找机会，而不是开放式扫描。最终找到的"机会"只是你已经知道的词的不同排列组合。

**正确做法：** 按 Section 4 约束——必须覆盖 ≥5 类不同用户任务场景。检查：这轮选的品类里有电商卖家吗？有自由职业者吗？有教育吗？有本地生活吗？如果全是"内容/营销/SEO/AI"→ 重选。

### 错误 9：需求族虚胖 ★ V5.2.2 新增

**表现：** 100 个候选词里，"AI caption generator""Instagram caption generator""TikTok caption generator"算成了 3 个独立机会。

**为什么是错的：** 它们解决的是同一个用户任务。虚胖会让机会数量看起来很多，实际上一轮只覆盖了 10–15 个真正的需求方向。

**正确做法：** 按 Section 5.7 聚类去重。每族最多保留 3 个代表词。100 个原始词 → 30 个需求族是正常的，不是"砍太多"。

### 错误 10：Keyword Planner 反向洗白 ★ V5.2.2 新增，V5.3 修订

**表现：** 前面已经判定冷启动不成立或一票否决触发，但看到 KP 搜索量不错，开始帮项目找理由——"虽然有挑战，但搜索量证明需求真实……"

**为什么是错的：** 搜索量只能验证规模，不能修复信任、合规、免费替代问题。Bank Statement Converter 搜索量再高，冷启动做不了就是做不了。V5.3 KP 前置后这个错误变得更隐蔽——因为 KP 在前面了，AI 更容易产生"KP 通过了所以方向没问题"的错觉，忽略了预验证还没做。

**正确做法：** KP 验证的是获客路径，不是全部。KP 通过 ≠ 可以 Build。KP 通过 + 冷启动审判通过 → 进入预验证。KP 通过 + 冷启动审判不通过 → Watch，不是 Build。KP 通过 + 预验证不通过 → Watch/Kill。

### 错误 11：预验证信号质量不达标 ★ V5.2.2 新增

**表现：** 5 个信号来自朋友说了"挺有意思"、3 个 Twitter 回复"good luck"，就算通过了。

**为什么是错的：** 熟人鼓励和礼貌性回复不是需求信号。它们不会转化为实际用户。

**正确做法：** 按 Section 14 信号分级——≥3 个有效信号（有效/强有效），≥1 个来自陌生人。"挺有意思""good luck"不计分，朋友鼓励不计分。

### 错误 12：用叙事替代强制表格 ★ V5.2.3 新增

**表现：** 到了该填 SERP 表格的地方，写了"官方帮助、教程、SVG repair/converter、Cricut 专门内容"。到了该填竞品定价表的地方，写了一段竞品描述。表格字段被改写成了段落叙事。

**为什么是错的：** 叙事可以模糊带过——"官方帮助、教程"没有告诉你前 5 名具体是谁、有没有小站、有没有强站垄断。表格强迫你逐格填数据，叙事允许你跳过。AI 天生偏好叙事（省 Token），但方法论需要的恰恰是表格（有结构、可检查）。

**正确做法：** 任何标注 ★ 的强制表格必须按原格式逐格填写。表格为空 → 不合格。表格被叙事替代 → 不合格。

### 错误 13：自行改写强制检查项 ★ V5.2.3 新增

**表现：** Section 12.5 的 12 条硬门检查被重写成了"自己理解的 12 条"。Section 16 的一票否决 7 条被重写。输出看起来在"精神上"对应，但具体条目不同。

**为什么是错的：** 这些检查项是经过多轮迭代校准的。每条检查的是特定问题。AI 改写之后，关键检查点可能被合并、省略或软化。例如原版第 9 条是"核心候选词搜索量已估算（非 Keyword Planner，公开数据即可）"——AI 改写版常变成"搜索意图明确"（完全不同的东西）。

**正确做法：** 强制检查项必须逐字使用原文。不得合并、不得改写、不得"用自己的话总结"。如果输出的检查项与原文不一致 → 不合格，重新按原文过。

### 错误 14：全程用中文描述而不给英文搜索词 ★ V5.2.3 新增

**表现：** 候选方向全部用中文描述性名称——"Cricut SVG 上传失败检查工具"、"Amazon FBA 分仓费计算器"——全程没有列出实际的英文搜索词。

**为什么是错的：** 用户搜的是英文。判断 SERP、搜索量、竞争格局，都需要英文搜索词。"Cricut SVG 上传失败检查"不是搜索词——"svg won't upload to cricut""cricut design space svg fix"才是。中文描述让你觉得"这是一个机会"，英文搜索词让你面对现实——这个词到底有没有人搜。

**正确做法：** 按 Section 5 硬约束——每个候选方向必须列出至少 3 个英文搜索词（主词/长尾词/变现词）。输出模板第 4 项（候选词簇）必须使用英文。

### 错误 15：混淆"公开搜索量估算"和"Keyword Planner" ★ V5.2.3 新增

**表现：** 说"Keyword Planner 还不能跑，所以这里不填搜索量"——把 Section 12.5 第 9 条的公开估算和 Section 13 的 KP 精确数据当成一件事。

**为什么是错的：** 这两个步骤目的不同、精度不同、时机不同。公开估算（Google 自动补全、Keywords Everywhere、Ahrefs 免费层）是方向级判断——"这个词是几十还是几千的量级"——在 Section 12.5 就必须做。KP 是精确确认——"这个词精确月搜索量 720"——在 Section 13、真人预验证之前做。跳过公开估算直接等 KP，等于在不知道方向大小的前提下进入精确验证。

**正确做法：** Section 12.5 第 9 条用的是公开免费数据，不需要 Google Ads 账号。给数量级（几十/几百/几千/几万）。Section 13 的 KP 是后一步的精确确认，且必须在 Section 14 真人预验证之前完成。两者不可混淆。

### 错误 16：合并四张核心表 ★ V5.2.4 新增

**表现：** 把 SERP 分析、竞品信息、免费替代、变现数据融合成一张"综合分析表"，或者把其中几张表的内容写成叙事段落而非独立表格。

**为什么是错的：** 四张表服务于四个独立判断——搜索进入难度、竞品是否赚钱、免费替代是否致命、变现是否现实。合并表模糊了这四个判断的独立性，让执行者可以"综合感觉不错"就跳过某一维度的硬伤。

**正确做法：** 按 Section 12.4 规则——四张表各自独立、各自完整、各自按原格式输出。不得合并为一张表，不得用叙事替代表格内容。

### 错误 17：SERP 表格写类型描述而非具体网站名 ★ V5.2.4 新增

**表现：** SERP 表格的"前5名构成"列填写"工具页 + 竞品页 + Reddit""官方帮助页面 + 第三方博客 + 论坛""mostly official docs and some blog posts"——写的是网站**类型**，而不是具体网站**名称**。

**为什么是错的：** "工具页"没有告诉你具体是哪个工具——是 pdfescape.com 还是 ilovepdf.com？前者可能只是轻量查看器，后者是完整的免费 PDF 处理套件。类型描述让你觉得"已经分析过了"，但实际上你仍然不知道前 5 名是谁、有没有小站、有没有强站垄断。

**正确做法：** 必须写出具体域名或网站名。例：`cricut.com, designbundles.net, reddit.com/r/cricut, sofontsy.com, youtube.com`。如果你写不出具体网站名，说明你没有实际打开 Google 看 SERP。

### 错误 18：跳过数据确认门直接进入预验证 ★ V5.3 新增

**表现：** 12 条硬门检查完成后，核心候选词公开估算全部为几十/月以下，但没有 Kill/Watch，直接进入了预验证阶段。或者 KP 报零但 Autocomplete/Reddit 有信号，直接 Kill 了方向。

**为什么是错的：** Section 12.5 新增的数据确认门是 V5.3 的核心变更——在投入 1-3 天人肉触达之前，必须先确认获客路径存在。公开估算全部为最低档 + 无非 SEO 路径 = 不值得预验证。但同时，KP 对长尾词报零是已知问题，不能仅凭 KP 报零就 Kill——需要 Autocomplete + Reddit 交叉验证。

**正确做法：** 12 条硬门检查完成后，先过数据确认门：核心候选词公开估算数量级 ≥ 几百/月 → 通过，进入 KP。全部为几十/月以下 → 检查是否有非 SEO 获客路径（Reddit 活跃讨论/Discord 群/YouTube 教程）。有 → 降级进入 KP。无 → 直接 Kill/Watch。KP 报零但 Autocomplete/Reddit 有信号 → 标记"KP 低估"，用非 SEO 路径替代 SEO 假设。
